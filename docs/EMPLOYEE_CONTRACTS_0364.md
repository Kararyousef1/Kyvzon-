## ① ★★★ شرطٌ ميّتٌ في جدارٍ أمنيّ

نصّ السياسة الحرفيّ من `pg_policy`:

```sql
((tenant_id = current_user_tenant_id())
  AND (current_user_is_staff()
       OR (employee_id = auth.uid())            ← ميّت
       OR (employee_id = current_user_employee_id())))
```

`employee_id` يشير إلى `employees.id` و`auth.uid()` هو `auth.users.id`.
مخرجات المسبار:

```
employees.id = 27d23175-e4ef-447e-802a-62e458d39a40
auth.uid()   = 11640001-0000-0000-0000-000000000001
يتساويان؟ false
صفوف employees حيث id = user_id: 0
```

⇒ الشرط **لا يُطابق صفّاً واحداً أبداً**. لا ضرر أمنيّ مباشر (الشرط
الثالث يعمل)، لكنه **شيفرة ميتة في جدار أمنيّ** تُوحي بأمانٍ مزدوج غير
موجود — وأيُّ تعديلٍ يُسقط الشرط الثالث سيبدو سليماً وهو ليس كذلك.

## ⑮ ★★★ الحساب بتوقيت المتصفّح — إثباتٌ بلحظةٍ ثابتة

`differenceInCalendarDays(new Date(end_date), new Date())` يعمل بمنطقة
المتصفّح. **لم أعتمد ساعة التشغيل** (درس 0327) بل لحظةً ثابتة:

```
2026-08-07 22:30 UTC  =  01:30 بغداد
  UTC   ⇒ 2026-08-07
  بغداد ⇒ 2026-08-08     ← يختلفان

عقدٌ ينتهي 2026-08-08:
  بـUTC   ⇒ «1 يوم»  (سارٍ غداً)
  ببغداد ⇒ «0 يوم»  (ينتهي اليوم)
```

⇒ بين منتصف الليل و03:00 بغداد، **كل** عقدٍ يُعرض بيومٍ زائد.

## ★ أخطائي في هذه الجولة — مُصحَّحة علناً

### 1. تصنيفٌ خاطئ لـ`INV01`

وضعتُ عكس «الشرط الميّت» في `RLS_CHECK` ظنّاً أن أثره أمنيّ فقط.
**خطأ**: التأكيد 1.1 يفحص **نصّ السياسة** في SQL مباشرةً فيمسكه.
نقلتُه خارج `RLS_CHECK` فسقط كما يجب.

### 2. `varchar(10)` في المسبار

`'ThIsIsGaRbAgE'` أطول من `salary_currency varchar(10)` فأجهض المعاملة
وحجب تسعة أعطال. استبدلتُه بـ`'XYZ'`.

### 3. `NUMERIC` يُطبع بمنزلتين

توقّعتُ `'1100000'` والصحيح `'1100000.00'` — درسٌ متكرّر منذ 0355.

### 4. خطأ lint في اختبار العقد نفسه

```
error  Spaces are hard to count. Use {2}  no-regex-spaces
```

مسافتان متتاليتان في regex (`created_by  :=` للمحاذاة في المايجريشن).
صحّحتُه بـ`{2}`. ★ هذه أول مرّة يظهر فيها **خطأ** lint (لا تحذير) في
السلسلة — وقد كان صفراً في كل الجولات السابقة.
