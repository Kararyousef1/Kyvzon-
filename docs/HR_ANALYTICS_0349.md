### ① ربط الصحة النفسية بالأقسام يُنتج صفراً أبداً

`AnalyticsPage.tsx:207`

```js
wellnessList.forEach((w) => {
  const emp = profileList.find((p) => p.id === w.employee_id);
```

والمفتاح الأجنبي المُحقَّق من المخطط (`0003_hr_platform_modules.sql:387`):

```
wellness_entries_employee_id_fkey
  FOREIGN KEY (employee_id) REFERENCES employees(id) ON DELETE CASCADE
```

و`employees.id` **≠** `profiles.id` — الجدولان مرتبطان عبر
`employees.user_id → profiles(id)`.

**ناتج التشغيل** (مستأجر حقيقي · موظفان · درجتان 30 و40):

```
wellness rows=2  avg_score=35
PAGE-LOGIC  join profiles.id = wellness.employee_id  => matches=0
CORRECT     join via employees.user_id               => matches=2
```

⇒ عمود «متوسط الصحة» **صفر لكل قسم أبداً**، وشريط التقدّم يُرسم بعرض
`0%` ويُلوَّن أحمر. كل قسم في المؤسسة يظهر في حالة حرجة.

**والأسوأ:** بطاقة «مؤشر الصحة» تعرض 35 صحيحاً (لأنها تجمع القائمة بلا
ربط) بينما الجدول يعرض 0. **رقمان متناقضان في الشاشة نفسها من المصدر نفسه.**

### ② «محلولة هذا الشهر» تخلط السنوات

`update_incidents_updated_at` عند **كل** تعديل — فبلاغ حُلّ في يناير

## ★ تصحيحان معلنان لأخطائي في هذه الجولة

### (أ) ادّعاء `neutral` السالب — **كان خاطئاً ولم أُدرجه**

ظننتُ ابتداءً أن `neutral = 100 - positive - negative` قد يصير سالباً.
حسبتُها يدوياً على الحدود: `positive ≤ 90` و`negative ≥ 5` ⇒ `neutral ≥ 5`
دائماً. **الادعاء باطل** فأسقطتُه قبل التوثيق.

### (ب) تصنيف `مجاز` — أسقطه التأكيد `SENTINEL_A2`

كتبتُ المقام أولاً بحذف `عطلة` وحدها. فأعطى 6 والمتوقَّع يدوياً 5.
السبب أن `مجاز` (إجازة معتمَدة) ليست `عطلة`. **احتساب الإجازة المعتمَدة
غياباً يظلم الموظف.** فصار الاستبعاد صريحاً، ويومَا العطلة والمجاز
يُعادان في عمودين مستقلّين (`out_leave_days` · `out_holiday_days`) مع
حارس جمع `SENTINEL_A5d` يتحقق أن `العمل + العطلة + المجاز = المجموع الخام`
كي لا يضيع صفّ من التصنيف صامتاً.

### (ج) نمط الهوية في سكربت RLS — أسقطه فشل السكربت

كتبتُ `set_config('request.jwt.claim.sub', uid, true)` وهي **محلّية
بالمعاملة**، وكل عبارة في `psql` معاملة مستقلّة ⇒ الهوية تضيع قبل
الاستدعاء فظهرت 16 حالة فشل كاذبة. النمط الصحيح `SET request.jwt.claim.sub`
على مستوى الجلسة.
