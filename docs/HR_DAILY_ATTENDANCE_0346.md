## الأعطال المُثبتة تشغيلياً

### ① `check_in` مقابل `check-in` — شرطة سفلية مقابل شرطة

```ts
// hr/AttendancePage.tsx:44-45
const checkIn  = empLogs.find(l => l.punch_type === 'check_in')?.punch_time;
const checkOut = empLogs.find(l => l.punch_type === 'check_out')?.punch_time;
```

القيد المُحقَّق:

```sql
CHECK (punch_type IN ('in', 'out', 'check-in', 'check-out'))
```

مُثبَت بالتشغيل:

```
INSERT ... punch_type='check_in'
  ⇒ new row for relation "attendance_logs" violates check constraint
    "attendance_logs_punch_type_check"
```

> **لا صفّ في القاعدة يمكن أن يطابق ما تبحث عنه الصفحة إطلاقاً.**
> `checkIn`/`checkOut` = `undefined` لكل موظف ⇒ الشرطان `if (checkIn && ...)` لا يُنفَّذان ⇒ الحالة `'غائب'` **للجميع دائماً** حتى لو بصم الجميع.

### ② لا بصمة خروج واحدة في النظام كلّه

`KioskPage.tsx:233` هو **الكاتب الوحيد**:

```ts
await attendanceService.create({
  employee_id, punch_time, shift_date, source, verification_type,
});                            // ← لا punch_type إطلاقاً
```

والعمود `DEFAULT 'check-in'`. مُثبَت بعد إدراج بصمتين (صباحاً ومساءً):

```
SELECT DISTINCT punch_type ⇒ «check-in»
بصمات الخروج في القاعدة    ⇒ 0
```

> حتى لو صُحِّحت الشرطة، `checkOut` يبقى `undefined` أبداً. لهذا **لا يكفي إصلاح الواجهة**: الدخول/الخروج يُشتقّان الآن من **ترتيب البصمات** لا من النوع.

### ③ ترشيح بمساواة لحظية

```ts

```

و`BaseService.findAll` يحوّل كل مُرشِّح إلى `.eq(key, value)` (مُحقَّق). أي **مساواة تامّة للحظة 00:00:00.000**.

مُثبَت: بصمتان اليوم · الصفوف المطابقة = **0**. و`todayEnd` مُحتسب في السطر 23 و**لا يُستعمل قط** — نفس نمط عطل `0337`.

### ④ عمودان معروضان بلا مصدر

`breakDuration: 0` و`currentDestination: ''` ثابتان، ويُعرضان كعمودين «مدة الاستراحات» و«موقع الاستراحة الحالي» — الأول `—` والثاني **خلية فارغة**.

والبيانات موجودة فعلاً: `employee_breaks` (17 عموداً) يملؤه `GatekeeperService` و`SupervisorBreaksPage`.

### ⑤ لا ترشيح ولا تاريخ ولا ملخّص

اليوم فقط، بلا منتقي تاريخ، بلا بحث، بلا ترشيح بالقسم أو الحالة، وبلا أي ملخّص. مديرُ موارد بـ300 موظف يرى 300 صفّ بلا أداة واحدة.

### قرارات تصميمية

- **الخروج من آخر بصمة إن تعدّدت فقط**: بصمة واحدة = دخول بلا خروج. اختلاق خروج يساوي الدخول يُظهر «عمل صفر دقيقة» بدل «ما زال مداوماً».
- **البصمة الصريحة تسبق الاشتقاق**: القاعدة لا تحوي أياً منها اليوم، لكن أجهزة ADMS قد ترسلها لاحقاً.
- **مدة الاستراحة الفعلية لا المصرّح بها**: استراحة انتهت في 12 دقيقة لا تُحتسب 15.
- **«في استراحة» تسبق «منصرف»**: تصريح مفتوح يحتاج إغلاقاً إدارياً — إخفاؤه خلف «منصرف» يُضيّعه.
- **يوم ماضٍ بلا انصراف ⇒ صفر دقائق**: لا نخترع ساعات حتى منتصف الليل.
- **الغائبون آخراً** في الترتيب.
- **الملخّص لا يتأثّر بالبحث**: «حاضر 12 من 200» يجب ألّا تتغيّر لأن المستخدم كتب حرفاً.
