## الأعطال المُثبتة تشغيلياً (قبل أي إصلاح)

### ① «الموظفون النشطون» = صفر دائماً

```ts
// HRDashboard.tsx:277
activeEmployees: emps.filter(e => e.status === 'active').length
```

الجدول **لا يحوي عمود `status`**:

```sql
SELECT count(*) FROM information_schema.columns
 WHERE table_name='employees' AND column_name='status';   ⇒ 0
 ... AND column_name='is_active';                         ⇒ 1
```

⇒ `e.status` هو `undefined` لكل صفّ. البطاقة تعرض **0** بينما الحقيقة 3.

> ★ والتناقض داخل الصفحة نفسها: السطر 162 يُرشّح `filters: { is_active: true }` — الاستعلام يعرف العمود الصحيح، ثم يُعاد الترشيح في المتصفح بعمود لا وجود له. والأسوأ أن الرقم «يبدو معقولاً» فلا يلفت النظر.

### ② الصحة النفسية لكل قسم = NaN

```ts
// HRDashboard.tsx:253
deptMap[d].wellnessTotal += w.mood_score;
```

`mood_score` **غير موجود في أي جدول في المخطط كلّه**:

```sql
SELECT table_name FROM information_schema.columns
 WHERE column_name='mood_score';   ⇒ (0 rows)
```

العمود الحقيقي `wellness_entries.score` (والجدول يحوي أيضاً `mood VARCHAR` نصّاً — غالباً مصدر الالتباس).

⇒ `+= undefined` ⇒ **NaN** يُعرض حرفياً، ويُستعمل في `width: ${dept.wellnessAvg}%` فينكسر الشريط.

> ★★ ولا يظهر في كل الحالات: الفرع `wellnessCount > 0 ? … : 75` يُخفيه حين لا سجلّات. فالأقسام الفارغة تعرض 75 «سليمة»، والأقسام **التي لديها بيانات فعلاً** هي وحدها التي تعرض NaN. العطل يضرب البيانات الحقيقية ويتجنّب الفارغة.

### ③ كل البلاغات تُنسب إلى قسم «عام»

```ts
// HRDashboard.tsx:246
const reporter = emps.find(e => e.id === i.reported_by);
```

`emps` من `employeeService` ⇒ `e.id` هو `employees.id`. لكن:

```
incidents_reported_by_profiles_fkey
  FOREIGN KEY (reported_by) REFERENCES profiles(id) ON DELETE SET NULL
```

التعريف الأصلي في `0003:192` كان `REFERENCES employees(id)` — و`0008:12-25` أسقطه وأعاد ربطه بـ`profiles`. الشيفرة بقيت على الافتراض القديم.

مُثبَت: مطابقات = **0** (`employees.id = 00097b65-…` · `reported_by = 9ee2fbb0-…`)

⇒ `problemCount` = صفر لكل قسم، والبلاغات تُنسب لقسم «عام» **غير موجود في الخريطة** أصلاً فيفشل `if (deptMap[dept])` وتُهمل تماماً. والأثر نفسه في `recentIncidents`: اسم المُبلِّغ لا يظهر أبداً.

### ④ بطاقة «مُصعَّدة لـ HR» ميّتة

```ts
incs.filter(i => i.status === 'escalated')
```

```
CHECK (status = ANY (ARRAY['pending','in_progress','resolved','closed']))
```

⇒ قيمة **يمنعها القيد**. بطاقة كاملة تعرض صفراً إلى الأبد.

### ⑤ الاتجاه الشهري يخلط السنوات

`getMonth()` يُهمل السنة ⇒ بلاغ مارس 2024 يُحتسب في مارس 2026. مع بيانات سنتين يصير الرسم مجموعاً تراكمياً لا اتجاهاً — نفس نمط عطل `0337`.

### ⑥ أرقام مُختلَقة تُعرض كمؤشّرات مُقاسة

- `satisfactionRate: 85` — ثابت بلا مصدر
- `trend="+2"` · `"-1"` · `"+5"` · `"-2"` — اتجاهات مكتوبة يدوياً
- `: 75` — متوسط عافية مُختلَق لكل قسم بلا بيانات

### ⑦ الحسابات كلها في المتصفح

`incidentService.findAll()` بلا حدّ + `wellnessEntryService.findAllEntries()` ⇒ كل بيانات الشركة تُنقل للمتصفح. اللوحة تبطؤ خطّياً بلا سقف.

## ★★★ خطأ ارتكبتُه أثناء العمل وصحّحتُه

كتبتُ `i.archived` والعمود الحقيقي **`archived_at`**. و**المايجريشن طُبِّق بنجاح** — لأن PL/pgSQL لا يفحص أجسام الاستعلامات عند الإنشاء، والاستدعاء الأول عاد مبكراً من فرع `tenant_id IS NULL` فلم يبلغ السطر المعطوب.

> **«طُبِّق بنجاح» ليس دليلاً على الصحة في PL/pgSQL.**

الحارس المضاف (`①.0`) يستدعي كل دالة **بمستأجر حقيقي** ويطالب بعدد صفوف قبل أي قياس.

### قرارات تصميمية

- **`wellnessSamples`** مع المتوسط: متوسط 82 من 3 عيّنات ليس كمتوسط 82 من 300.
- **متوسط العافية على الموظفين لا الإدخالات**: موظفٌ سجّل 30 مرّة لا يطغى على متوسط قسمه. الفرق مُقاس: **80** مقابل 77.
- **`criticalOpen`** لا `critical`: عدّ المُغلقة ضمن إنذار يجعله يرتفع أبداً ولا ينخفض.
- **`unassigned`** بديل `escalated`: حالة حقيقية تحتاج تدخّلاً.
- **`NULL` لا صفر** ليوم بلا بيانات: صفر في رسم نفسيّ = «أسوأ حالة ممكنة».
- **كلها `INVOKER`**: RLS هو الحارس، لا الدالة.

## ثغرات تغطية اكتشفتُها في اختباري وأصلحتُها

| # | الثغرة | الإصلاح |
|---|---|---|
| ① | ثلاثة عكوس مرّت (`critical` يشمل المُغلقة · `unassigned` كذلك · `resolved_month` بلا حدّ) لأن بياناتي **لا تحوي الحالة التي تُفرّق** — لم يكن ثمة بلاغ حرج مُغلق، ولا مُغلق بلا مُسنَد، ولا محلول خارج الشهر | أضفتُ `ب6`: `closed`+`critical`+بلا مُسنَد+الشهر الماضي — صفٌّ واحد يُغطّي الثلاث. **شرطٌ لا تُوجَد بيانات تخالفه = شرط غير مُختبَر.** |
| ② | سكربت RLS أبلغ «تسريب خصوصية»: موظف يرى `60` وهو متوسط الشركة. **تشخيصي كان خاطئاً** — RLS يعمل صحيحاً، لكن درجة الموظف (60) صادفت أن تساوي المتوسط (80+60+40)/3 | قيم مميِّزة: 90·62·40 ⇒ متوسط **64** ودرجة الموظف **62**. + دليل موجب: `wellnessSamples = 1` لا 3 |
| ③ | تنظيف سكربت RLS يفشل **صامتاً**: محفّز `trg_block_incident_delete` (0341) يمنع الحذف و`\|\| true` يبتلع الخطأ. تراكمت 9 بلاغات من 3 جولات ⇒ «الإجمالي = 6» بدل 2 | `DISABLE TRIGGER` لحظياً (نمط `0341`) + **حارس** يتحقّق أن التنظيف نجح فعلاً قبل التجهيز |
| ④ | اختباران سقطا لأنهما بحثا في ملف باسم خاطئ (`0001_core_foundation` غير موجود) وطابقا نصّ `COMMENT` الذي **يشرح العطل** | `0001_core_schema` + `sqlStatementsOnly()` يزيل السلاسل النصّية، مع اختبار ذاتي للمُجرِّدات الثلاثة |
