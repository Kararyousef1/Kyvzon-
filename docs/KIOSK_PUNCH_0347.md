## الأعطال المُثبتة تشغيلياً

### ① كل بصمة تُسجَّل «دخولاً»

```ts
// KioskPage.tsx:233 — الكاتب الوحيد لـattendance_logs
await attendanceService.create({
  employee_id, punch_time, shift_date, source, verification_type,
});          // ← لا punch_type ولا shift_type
```

والعمود `DEFAULT 'check-in'`. مُثبَت بعد بصمتَي 08:00 و17:00:

```
SELECT DISTINCT punch_type ⇒ «check-in»
بصمات الخروج               ⇒ 0
بصمات بلا shift_type        ⇒ 2
```

⇒ **بصمة الانصراف تُسجَّل «دخولاً»**. والسطر 584 يعرض الوردية فيظهر «—» أبداً.

> ★★ هذا هو العطل الذي وثّقه `0346`: لوحة الحضور اليومي اضطرّت لاشتقاق الخروج من **ترتيب** البصمات لأن النوع لا يُكتب أصلاً.

### ② «حاضر: 0» مهما بصم الجميع

```ts
const present = summaries.filter(s =>
  s.status === 'حضور_بوقت' || s.status === 'متأخر' || …).length;
absent: empList.length - present - onLeave
```

و**لا شيء في المنصّة كلّها يكتب `attendance_summary` من البصمات**:

```
صفوف attendance_summary بعد بصمتين = 0
محفّزات على attendance_logs        = 0
دالة refresh_attendance_summary    = 0
```

الكاتب الوحيد للجدول هو اعتماد الإجازات — فيمتلئ بـ`'مجاز'` ولا يعرف الحضور الفعليّ.

⇒ الحارس يعمل طوال اليوم واللوحة تقول «حاضر: 0 · غائب: 47»، وحالة كل موظف فارغة.

> ★ `leaveAttendanceLink.ts:189` كان يستدعي `refresh_attendance_summary` منذ البداية — وهي غير موجودة (وثّقتُ ذلك في `0344` وأزلتُ الاستدعاء الميّت). **هنا أبنيها فعلاً.**

### ③ النوع من عدّ المصفوفة لا من آخر بصمة

```ts
return empLogs.length % 2 === 0 ? 'check_in' : 'check_out';
```

منطق تناوب ينقلب كلّه لو ضاعت بصمة واحدة (شبكة · تكرار مُبتلَع في `catch`). والقيد `UNIQUE (tenant, employee, punch_time)` يمنع التطابق **التامّ** فقط — بصمتان بفارق ثانية تمرّان.

### ④ لامبدا مشوّهة

```ts
.filter((s: any , EmployeeStatus) => …)   // :163 و:166
```

المعامل الثاني اسمه `EmployeeStatus` — يُظلّل النوع المستورد ويستقبل **الفهرس**.

## ★★★ عطلان في شيفرتي أنا كشفهما الاختبار

هذان لم يكونا في الصفحة — كتبتُهما في `0347` والاختبار أسقطهما:

### أ) الحالة من وجود بصمة خروج لا من آخر بصمة

كتبتُ `WHEN p.out_at IS NOT NULL THEN 'منصرف'`. فمن بصم دخولاً ثم خروجاً **ثم عاد ودخل** (3 بصمات) يظهر «منصرف» — وهو داخل المنشأة الآن.

```
★ بعد 3 بصمات: status=منصرف n=3 next=check-out
```

الإصلاح: الحالة تتبع `p.last_type`.

### ب) الساعة بمنطقة الخادم لا ببغداد

```
SHOW timezone         ⇒ Etc/UTC
EXTRACT(HOUR FROM '2026-03-16 07:00:00+03')                      ⇒ 4
EXTRACT(HOUR FROM (… AT TIME ZONE 'Asia/Baghdad'))               ⇒ 7
```

⇒ موظف الوردية الصباحية يُصنَّف «ليلي»، و**كل موظف يُحتسب له 180 دقيقة تأخير وهميّ**.

> ★ والفارق يظهر فقط حين تختلف منطقة الخادم عن منطقة المنشأة — أي **في الإنتاج لا في جهاز المطوّر**. أضفتُ حارساً يتحقق أن الجلسة ليست على بغداد قبل الفحص، وإلا لما قاس شيئاً.

### قرارات تصميمية

- **النوع من آخر بصمة فعلية** لا من عدّ مصفوفة — لا ينقلب بضياع بصمة.
- **نافذة ارتداد 60 ثانية**: إصبعٌ يلمس القارئ مرّتين ليس بصمتين.
- **الملخّص لا يمسّ الإجازة**: `مجاز`/`إجازة_انتظار`/`عطلة` قرار إداريّ — بصمةٌ عارضة يجب ألّا تمحوه.
- **الخروج من آخر بصمة إن تعدّدت فقط** — لا نختلق خروجاً يساوي الدخول (درس `0346`).
- **الساعات صفر لمن لم ينصرف** — لا تُحتسب حتى `NOW()`.
- **`kiosk_punch` DEFINER**: سياسة INSERT تشترط `current_user_is_staff()` = admin·hr·developer·it_admin — والحارس قد يكون `supervisor`/`gatekeeper`. مُثبَت بـRLS أن الإدراج المباشر يُصدّ.
