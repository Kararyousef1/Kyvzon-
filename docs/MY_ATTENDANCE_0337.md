## ★★★ العطل ① — الشهر المختار لا يُرشَّح إطلاقاً

الصفحة تحسب حدود الشهر في السطر 175:

```ts
const startDate = format(new Date(currentYear, currentMonth, 1), 'yyyy-MM-dd');
const endDate   = format(new Date(currentYear, currentMonth + 1, 0), 'yyyy-MM-dd');
```

ثم **لا تُمرّرهما لأي استعلام**. مُحقَّق:

```bash
$ grep -n 'startDate\|endDate' src/pages/employee/MyAttendancePage.tsx
175:      const startDate = …
176:      const endDate   = …
```

سطرا التعريف فقط — **لا استعمال واحد**.

```ts
attendanceSummaryService.findAll({
  filters: { employee_id: employeeId },   // ← بلا نطاق
  orderBy: 'shift_date', ascending: false,
})
```

## ★★★ العطل ② — `weeklyStreak` عدٌّ لا تتابع

```ts
weeklyStreak: Math.min(summaryData.filter(s => s.status !== 'غائب').length, 7)
```

هذا **عدّ** لا **تتابع**. موظف حضر يوماً وغاب يوماً على مدى أسبوعين
يحصل على «7 أيام متتالية» — بينما أطول تتابع لديه **1**.

الإثبات في الاختبار (`5.4`): تناوب حضور/غياب لأربعة عشر يوماً
⇒ الصيغة القديمة `min(7,7)=7` · الحقيقة `1`.

### وقرار دقيق: الفجوة لا تكسر التتابع

عطلة نهاية الأسبوع **لا تُسجَّل أصلاً** في `attendance_summary`. لو
كسرنا السلسلة عند كل يوم بلا سجلّ لما تجاوز التتابع 5 أبداً. نكسرها
عند **الغياب المُسجَّل** وحده.

### و`'إجازة'` مستثناة عمداً

الإجازة المعتمَدة ليست حضوراً ولا انقطاعاً. احتسابها حضوراً يُضخّم
التتابع زوراً — يومان إجازة بين يومَي حضور يعطيان `4` بدل `2`.

## ★★ قرار ثالث: المتوسط على أيام الحضور

```sql
sum(total_hours) FILTER (WHERE status IN ('في الوقت','متأخر','حاضر'))
/ NULLIF(count(*) FILTER (WHERE status IN (…)), 0)
```

القسمة على أيام **تشمل الغياب** تُظهر متوسطاً أقلّ من الحقيقة:
`15 ساعة / 3 أيام = 5` بينما الصحيح `15 / 2 = 7.5`.

### قرارات تقنية

**الحدود تُحسب في القاعدة لا تُستقبَل نصّاً** — تمرير تاريخين من
المتصفح يعني الوثوق بمنطقته الزمنية؛ موظف في بغداد قد يرى شهراً
مختلفاً عن زميله لو تغيّر إعداد جهازه.

**الحدّ الأعلى حصري** (`< v_to` لا `<=`) — لا تداخل بين الشهور.

**صفّ أصفار للشهر الفارغ** لا «لا شيء»: الواجهة تعرض بطاقات إحصاء
دائماً، وغياب الصفّ يجعلها `undefined` فتظهر `NaN`.

**الحالات نصوص عربية حرّة بلا `CHECK`** — استخرجتُها من المايجريشنات:
`'غائب'`(10) · `'متأخر'`(7) · `'في الوقت'`(6) · `'حاضر'`(4) ·
`'إجازة'`(3).

### ★★★ ثغرتان في تغطيتي — كشفهما العكس

**العكسان ④ و⑥ لم يُسقطا الاختبار في المحاولة الأولى.**

**ثغرة ④:** لم يكن في الاختبار سجلّ واحد بحالة `'إجازة'` — فتوسيع
قائمة الحالات لتشملها لم يُغيّر شيئاً. كنتُ أحرس قراراً بلا بيانات
تختبره. أضفتُ السيناريو `5.8`.

**ثغرة ⑥:** نفس درس `0335` — `employee_id` معرّف UUID **فريد عالمياً**،
فترشيحه وحده يُقصي الصفوف الأجنبية ضمناً. كنتُ أقيس عزلاً **يحدث
بالصدفة لا بالتصميم**.

الكشف الحقيقي يحتاج **نفس `employee_id` تحت مستأجرين** — حالة ممكنة
لأن `attendance_summary.employee_id` **بلا مفتاح أجنبي** يربطه
بمستأجره. أضفتُ التأكيدين `3.8` و`3.9`.

وقد أثبتُّ سقوط العكسين بعد السدّ:
