# إغلاق المرحلة الخامسة — تكامل بوابتَي الموظف والموارد البشرية

**التاريخ:** 2026-08-15
**الحالة:** مكتملة تطويرياً ومحلياً؛ التطبيق Runtime للمهاجرات `0374`–`0378` ونشر Edge Function ما زالا تشغيليين.

## النتيجة

أُغلقت بنود المرحلة الخامسة العشرة دون إعادة بناء البوابات، وبمهاجرات تراكمية فقط:

| البند | الإغلاق |
|---|---|
| التواصل Employee↔HR | `0374`: إنشاء الحالة والرسالة ذرياً وإظهار رد HR في خيط الموظف |
| اعتماد HR واليتامى | `0375`: صفر مستهلك React للمحرك القديم، سجل يتامى، مصالحة وحارس inbox |
| Hire→Auth→Contract | `0376`: draft contract + onboarding + Auth invitation outbox |
| Offboarding→Contract→Auth | `0376`: إغلاق العقد + تعطيل Auth عبر outbox قابلة لإعادة المحاولة |
| Bonus→Payroll | `0377`: claim للمكافآت المعتمدة داخل فترة الراتب، ربطها بالسجل، وصرفها ذرياً مع الفترة |
| Succession→Training | `0377`: خطة تطوير مرتبطة بدورة وتكليف `course_progress` وإكمال تلقائي للخطة |
| التنفيذ الفعلي للزمنيات | `0378`: ربط الطلب بسجل التنفيذ وتسجيل actual out/return من واجهة staff |
| امتثال SOP | واجهة `AdminSOPsReport` تقرأ `sop_compliance_overview` عبر `sopService` |
| صحة أجهزة البصمة | واجهة حضور HR تعرض `biometric_devices_health` عبر `TechMetricsService` |
| الحركة وتدريب الموظف | رابط HR لإنشاء تصريح في بوابة الحركة، ومشغل محتوى heartbeat وشاشة اختبار حقيقية |

## 0377 — Bonus → Payroll

- أضيفت روابط tenant-scoped من المكافأة إلى فترة الراتب وسجل الموظف.
- `payroll_run` يحتفظ بحساب 0348 ثم يطالب فقط بالمكافآت:
  - `approved`
  - غير المؤرشفة
  - المتقاطعة زمنياً مع فترة الراتب
  - غير المرتبطة بفترة أخرى
- يُعاد حساب `payroll_records.bonus_amount` من مجموع الروابط، ثم `net_salary`.
- إعادة التشغيل لا تضاعف المكافأة.
- الدفع اليدوي `approved → paid` من شاشة المكافآت محجوب؛ الدفع يأتي من `payroll_mark_paid` فقط.
- `payroll_mark_paid` يحول الفترة والسجلات والمكافآت المرتبطة إلى `paid` في معاملة واحدة، ويسجل `paid_by/paid_at`.
- صفحة الرواتب تعرض نافذة «تأكيد الصرف»، وصفحة المكافآت تعرض فترة الراتب أو «بانتظار تشغيل الرواتب».

## 0377 — Succession → Training

- أضيفت روابط tenant-scoped من `succession_development_plans` إلى `courses` و`course_progress`.
- خطة `training/certification` لا تُنشأ بلا دورة.
- إنشاء الخطة يكلف موظف المرشح بالدورة في المعاملة نفسها.
- تقدم الدورة يحول الخطة إلى `in_progress`، وإتمامها يحولها إلى `completed` تلقائياً.
- لا يمكن إعلان خطة تدريب مكتملة يدوياً قبل اكتمال `course_progress`.
- الخطة لا تُحذف؛ تُلغى بسبب محفوظ.
- صفحة التعاقب تعرض خطط المرشح والدورة والتقدم وتسمح بإنشاء التكليف.
- صفحة الموظف أصبحت مشغل محتوى فعلياً:
  - `training_progress_touch` عند الفتح.
  - heartbeat كل 30 ثانية والباقي عند الإغلاق.
  - تحميل الاختبارات من `QuizService`.
  - تسليم المحاولة عبر `training_quiz_submit`.
  - نجاح الاختبار يكمل الدورة وخطة التعاقب المرتبطة.

## 0378 — التنفيذ الفعلي للزمنيات

- أضيف `permissions.source_request_id` مع FK مركب داخل المستأجر و`ON DELETE RESTRICT`.
- عولجت السجلات السابقة بربط حتمي دون تكرار.
- `permission_execution_record`:
  - staff-only.
  - يقبل طلباً معتمداً فقط.
  - يلزم الخروج الفعلي، ويلزم العودة لغير «مغادرة».
  - يمنع العودة قبل الخروج.
  - يسجل المنفذ والوقت والملاحظة.
- `PermissionsPage` تعرض التنفيذ الفعلي وتوفر نافذة تسجيل/تحديث للطاقم المخول.

## واجهات التكامل المتوسطة

### SOP

أضيف تبويب «امتثال الإجراءات» في `AdminSOPsReport` يستخدم `sopService.compliance()`، أي RPC `sop_compliance_overview`، ويعرض المستهدفين والقراء والمعتمدين والنسبة.

### البصمة

تعرض `AttendancePage` صحة الأجهزة، آخر مزامنة، التأخر، حالة stale، وبصمات اليوم من `biometric_devices_health`.

### الحركة

أصبحت واجهة HR للحركة توفر «تصريح حركة جديد» إلى المسار الحقيقي `/app/movement/employee/permits/new`. بوابة الحركة نفسها كانت موجودة وتقبل دور HR؛ الدين كان غياب نقطة دخول من واجهة HR.

### التدريب

اكتملت فجوة `touch()` والاختبار في `TrainingPage`; لا يبقى `time_spent` و`last_access_at` بلا كاتب من المشغل.

## قرار `hr_approval_steps`

المرحلة الخامسة لا تدّعي حذف الجدول. القرار الموثق في `HR_APPROVAL_ENGINE_CONSOLIDATION_0375.md` ما زال سارياً:

- واجهات React وSDK القديمة = صفر.
- الطلبات اليتيمة لا تعبر inbox.
- PostgreSQL ما زالت تحوي قراء وكتاباً حيين في الإجازات والاستئذانات والسلف والمصروفات وحراس الحالة.
- لذلك إسقاط الجدول الآن غير آمن، ويظل تفكيكه migration معمارية مستقلة لا شرطاً مصطنعاً لإغلاق تكاملات البوابات.

## المطلوب Runtime

لا يدعي هذا الإغلاق تطبيق المهاجرات أو نشر الوظيفة في البيئة الفعلية. يلزم بالترتيب:

1. تطبيق `0374`، `0375`، `0376`، `0377`، `0378`.
2. نشر `employee-lifecycle-identity` وضبط أسرارها و`APP_ORIGIN`.
3. Smoke متعدد الأدوار والمستأجرين:
   - تواصل الموظف ورد HR.
   - اعتماد/رفض/إلغاء وطلب يتيم.
   - توظيف ودعوة وفشل/retry وإنهاء خدمة.
   - تشغيل راتب بمكافأتين، إعادة التشغيل، الاعتماد، الصرف.
   - خطة تعاقب وتكليف دورة وheartbeat واختبار وإكمال.
   - تسجيل actual out/return.
   - امتثال SOP وصحة جهاز بصمة وإنشاء تصريح حركة.

بعد الإغلاق المحلي للمرحلة الخامسة، المسار التطويري التالي هو **المرحلة السادسة**: خفض ديون UX المقاسة، الوصول والجوال، ثم مصفوفة Runtime/E2E الشاملة.
