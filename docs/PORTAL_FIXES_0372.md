# إصلاح أعطال بوابتي الموظف والموارد البشرية — المايجريشن 0372

**بلاغ المستخدم:** 2026-08-08، بعد تطبيق المايجريشنات `0332`–`0371` بنجاح.
**القاعدة:** Postgres 17 محليّ · قاعدةٌ نظيفةٌ بـ301 مايجريشن.

---

## ⓪ ما بلّغ عنه المستخدم — حرفياً

> «المشكله الاولى في بوابه الموظف في صفحات الاجازات والزمنيات يضهر
> للموظف كما يضهر للموارد البشريه طلباتي والتي بانتضار قراره وسجلات
> الشركه كذالك هناك امور لاتحفظ في بوابه الموظف كذالك يضهر في بوابه
> الموارد البشريه خطا يقول
> `HRDashboard.tsx:281 فشل تحميل لوحة الموارد: TypeError: incList.forEach is not a function`»

**ثلاثة بلاغات ⇒ خمسة أعطال مُثبتة تشغيلياً.**

## ① ★★★★ «أمورٌ لا تُحفظ» — كلُّ طلب إجازةٍ سنويّةٍ يُرفض حتماً

### الإثبات

`_probe_0372.sql` — استدعاءٌ حقيقيٌّ بدور `authenticated`:

```
④أ submit_leave_request('سنوية', اليوم+10, اليوم+12, …)
   ⇒ فشل: LEAVE_INSUFFICIENT_BALANCE: الرصيد المتبقّي -3.000 يوم
```

### السبب الجذريّ

`0002_employee_features.sql:97`:

```sql
annual_total NUMERIC(6,3) NOT NULL DEFAULT 0,
```

و`submit_leave_request` تُنشئ الصفَّ بثلاثة أعمدةٍ فقط:

```sql
INSERT INTO public.leave_balance (tenant_id, employee_id, year)
VALUES (v_tenant, v_emp, v_year)
ON CONFLICT DO NOTHING;
...
IF v_taken + v_days > v_total THEN RAISE EXCEPTION 'LEAVE_INSUFFICIENT_BALANCE…'
```

**وفحصتُ المشروع كلَّه (301 مايجريشن + كلّ الدوال + كلّ المحفّزات):**

| ما يذكر `annual_total` | الفعل |
|---|---|
| `submit_leave_request` | **يقرؤه** |
| `my_leave_balance` | **يقرؤه** |
| محفّزات `leave_balance` | `updated_at` وحده |

> **صفرُ سطرٍ في المشروع يملؤه.** العمود يبقى صفراً إلى الأبد،
> وحارسُ الرصيد يرفض كلَّ طلبٍ لكلّ موظفٍ دائماً.

### العلاج (قرار المستخدم: «سياسة لكل منشأة»)

| العنصر | الوصف |
|---|---|
| `leave_policies` | سياسةٌ لكلّ منشأة: 21 يوماً + يومٌ لكلّ 5 سنوات، بحدٍّ أقصى 30 |
| `leave_entitlement()` | الأقدميّة + التناسب في سنة الالتحاق |
| `ensure_leave_balance()` | يفتح الرصيد ولا يهبط برصيدٍ مُنِح يدوياً (`GREATEST`) |
| `trg_seed_leave_balance` | محفّزٌ على `employees` — كلُّ موظفٍ جديدٍ برصيد |
| `trg_seed_leave_policy` | محفّزٌ على `tenants` — كلُّ منشأةٍ جديدةٍ بسياسة |
| ملءُ القائمين | حلقةٌ في المايجريشن تفتح أرصدة كلّ الموظفين الحاليين |
| `leave_policy_board/update()` | للموارد البشرية: عرضُ السياسة وتعديلُها وإعادةُ الحساب |

## ② ★★★★ «يظهر للموظف كما يظهر للموارد البشرية»

### الإثبات

`LeaveRequestPage.tsx:314-316` و`PermissionsPage.tsx:286-288` تعرضان
ثلاثة تبويباتٍ **لكلّ مستخدمٍ بلا شرط دور**:

```
طلباتي · بانتظار قراري · سجلّ الشركة
```

`_probe_0372.sql` — موظفٌ عاديّ (`employee`) بدور `authenticated`:

```
نطاق mine  ⇒ 1 صفّ
نطاق inbox ⇒ 0 صفّ
نطاق all   ⇒ 1 صفّ   ← ضغط «سجلّ الشركة» فرأى شيئاً
```
والموارد البشرية على النطاق نفسه ⇒ `2 صفّ`.

★ **إنصافاً: RLS تحرس** — الموظف رأى صفَّه هو لا صفَّ زميله.
لكنّ التبويب ظهر فأوهمه أنّه يطالع سجلّ الشركة، و«بانتظار قراري»
ظهر لمن لا قرارَ له. **الإيهامُ عطلٌ وإن لم يُسرّب.**

و`PROBE_5`: حارسُ الدور داخل الدالتين = **صفر**.

### العلاج (نصُّ المستخدم: «الموظف فقط يطلب اجازه او زمنيه ويرى طلباته فقط»)

- `can_use_request_scope(scope, type)` — `mine` للجميع · `all` للموارد
  البشرية والإدارة · `inbox` لمن له **خطوةُ اعتمادٍ فعليّة في هذا النوع**.
- الحارس **محقونٌ في `leave_requests_view` و`permission_requests_view`**
  ⇒ `LEAVE_SCOPE_FORBIDDEN` / `PERM_SCOPE_FORBIDDEN`.
- الصفحتان تسألان القاعدة قبل رسم أيّ تبويب، والشريط يختفي كلّياً
  للموظف العاديّ. **الإخفاءُ في الواجهة ليس منعاً — المنعُ في القاعدة.**

## ③ ★★★★ `incList.forEach is not a function`

`IncidentService.hrInbox()` تُعيد **صفحةً** `{ rows, total }` لا مصفوفة.
و`HRDashboard.tsx:192`:

```ts
incidentService.hrInbox
  ? incidentService.hrInbox({ limit: 5 })   // ← يفحص وجودَ الدالة
  : incidentService.findAll({ limit: 5 }),  //    لا شكلَ ناتجها
```

فمرّ الكائنُ إلى `incList.forEach` (السطر 231) **فانفجرت اللوحة كاملةً**.

**العلاج:** `.then((p) => p.rows)` + حارسُ `Array.isArray`.
وصُحِّح الموضعان في `_archived/ProblemsList.tsx` بالعطل نفسه.

## ⑤ انحدارات كشفها الفحص الشامل — وأصلحتُها

### ★★★★ ① `ON UPDATE CASCADE` مفقود — كسر ثلاثة سكربتات (14 فحصاً)

محفّزي `trg_seed_leave_balance` صار يُنشئ صفَّ رصيدٍ لكلّ موظف،
وسكربتات `0344`/`0345`/`0346` تُبدّل `employees.id` بـ`UPDATE` لتثبيت
معرّفاتٍ معلومة. والمفتاح كان `ON DELETE CASCADE` **بلا** `ON UPDATE`:

```
ERROR: update on table "employees" violates foreign key constraint
       "leave_balance_employee_id_fkey"
```

فسقطت **تهيئةُ ثلاثة سكربتاتٍ كاملةً**.

> ★ **الدرس المنهجيّ:** محفّزٌ جديدٌ يُنشئ صفوفاً تابعةً يفرض مراجعةَ
> كلّ مفتاحٍ يشير إلى الجدول الأصل — لا مفاتيحِ الجدول الجديد وحدها.

★ وقبل الإصلاح **أثبتُّ أنّ السبب مايجريشني**: شغّلتُ السكربتات الثلاثة
على قاعدةٍ بلا `0372` فنجحت جميعاً.

### ★★ ② سكربتا `0339`/`0340` يتوقعان مرورَ النطاق `all`

كانا يفحصان «RLS يحكم فيُعيد صفراً». وقد صار المنعُ **أقوى**:
استثناءٌ صريح. حُدِّث التأكيدان ليقبلا الحالتين، مع تعليلٍ صريح
بأنّ هذا **تشدُّدٌ لا انحدار**.

## ⑥ أخطائي في هذه الجولة — مُصحَّحةٌ علناً

1. ★★★ **بذرُ السياسة يعمل مرّةً واحدة** — كشفه التأكيد 1.0: عبارةُ
   `INSERT … SELECT FROM tenants` تعمل وقتَ المايجريشن فقط، والمنشأةُ
   التي تُنشأ بعده تُولد بلا سياسة **فيعود العطل ① كاملاً لكلّ عميلٍ
   جديد**. العلاج: محفّزٌ لا عبارة.
2. ★★★★ **الاسترجاع في سكربت العكس كان معطوباً** — الحقنُ مشروطٌ بغياب
   العلامة، ودالّةٌ عُكس حقنُها بـ`IF FALSE` **تحتفظ بالعلامة نصّياً**
   فتتخطّاها إعادةُ التطبيق ويبقى العكسُ سارياً. أفسد ذلك كلَّ
   الانعكاسات بعد `INV11`. العلاج: `_undo_0372_inversion.sql`.
3. ★★★★ **«حارسٌ سابق يمسك الحالة» مرّتين**:
   - `INV7`: كلُّ منشأةٍ في العيّنة لها سياسةٌ بحكم المحفّز، فاحتياطُ
     «منشأةٍ بلا سياسة» لم يُختبَر. أُضيف التأكيد `2.7`.
   - `INV14`: القيمة `60` تجاوزت `annual_days_max` فرفضها `CHECK`
     **قبل** RLS ⇒ بدا المنعُ ناجحاً وسياسةُ RLS غيرُ مُختبَرة.
     العلاج: قيمةٌ صالحةٌ للقيد (`22`) وعدُّ الصفوف بـ`RETURNING`.
4. ★★ **خمّنتُ أسماءً بدل قراءتها** — `requested_by` في
   `hr_approval_requests` (الصواب `employee_id`) و`trg_block_service_center_delete`
   (الصواب `trg_block_hr_case_delete`) و`'تأخير'` في مفردات الزمنيات
   (الصواب `عادية · مغادرة · تعويضية · بدون_راتب`).
5. ★★ **استبدالٌ بسلسلةٍ فارغة يكسر SQL** (درس 0371/INV17 يتكرّر) —
   في `INV10`/`INV19`؛ العلاج `AND TRUE` / `WHERE TRUE`.
6. ★ **`psql -t -A` لا يطبع «UPDATE n»** فبقي `ROWS` فارغاً؛ العلاج
   `RETURNING 1` وعدُّ الأسطر.
7. ★ **`rstrip('"')` في سكربت Python** ترك `fi"` فكسر بنية bash.
