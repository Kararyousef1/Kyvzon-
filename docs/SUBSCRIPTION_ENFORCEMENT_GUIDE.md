# الإقفال الحقيقي — الاشتراك يحرس القاعدة

**التاريخ:** 2026-08-05 · **المايجريشن:** `0320`
**⚠️ الوضع الافتراضي `off` — لا يتغيّر شيء حتى تُشغّله بنفسك**

---

## الحجم الحقيقي للثغرة — أكبر مما قدّرتُ

التحقيق قبل الكتابة كشف أن المشكلة ليست «بوابة تمرّ» بل **غياب البوابة أصلاً**:

| البوابة | جداولها | محروسة بالاشتراك |
|---|---:|---:|
| المخزون | 142 | **0** |
| التصنيع | 106 | **0** |
| CRM | 37 | **0** |
| المشتريات | 14 | **0** |
| العقود | 11 | **0** |
| | **310** | **صفر** |

والبوابة القائمة (`hybrid_allows_module`) تغطي 103 جداول في خمس وحدات فقط — وتنتهي بـ:

```sql
WHEN NOT current_user_is_hybrid() THEN true    -- ★ كل شركة غير هجينة تمرّ
```

**مسبار على شركة `basic` بـ`enabled_modules={employee}`:**
```
hybrid_allows_module('finance')   = TRUE
hybrid_allows_module('inventory') = TRUE
```

---

## ★★ المخاطرة التي حكمت التصميم كله

```sql
tenants.enabled_modules  DEFAULT ARRAY['employee']
```

ولا شيء في القاعدة يقرأه إلا دالتان. أي أن **معظم شركاتك قيمتها ناقصة أو غير محدَّثة**.

> **إقفال فوري صارم = قطع كل بوابة لكل عميل يعمل الآن.**

لذلك بنيتُ الآلية كاملة، وشغّلتُها بـ**مفتاح أمان لكل مستأجر** يبدأ عند `off`.

---

## الأوضاع الثلاثة

| الوضع | السلوك | الاستعمال |
|---|---|---|
| **`off`** | يمرّ كل شيء — **السلوك الحالي حرفياً** | الافتراضي · لا تغيير |
| **`audit`** | يمرّ **ويُسجَّل** في `subscription_access_log` | التجربة الآمنة |
| **`enforce`** | **يُمنع** فعلياً | الإقفال الحقيقي |

### مُثبَت تحت RLS حقيقي (`SET ROLE authenticated`)

شركة `basic` · `{employee,hr}` · لديها صنف مخزون:

| الوضع | مخزون (خارج الاشتراك) | ملفات (داخله) | السجل |
|---|---:|---:|---|
| `off` | **1** ← لا تغيير | 1 | — |
| `audit` | **1** ← يمرّ | 1 | `would_block` |
| `enforce` | **0** ← مُنِع | **1** ← سليم | `blocked` |

---

## ★ ثلاثة حرّاس ضد الكارثة

### ① وحدات لا تُقفَل أبداً

```
employee · admin · tawathul
```

بلا `employee` لا يستطيع أحد استعمال حسابه، وبلا `admin` لا يستطيع مدير النظام **إصلاح الإعداد** — قفل لا مخرج منه.

مُختبَر حتى مع تفريغ `enabled_modules` بالكامل.

### ② التدرّج إلزامي

```sql
IF current = 'off' AND p_mode = 'enforce' THEN
  RAISE EXCEPTION 'MUST_AUDIT_BEFORE_ENFORCE';
```

**لا يمكن القفز من `off` إلى `enforce`.** يجب المرور بـ`audit` ورؤية الأثر.

### ③ السياسات مقيِّدة لا موسِّعة

```sql
CREATE POLICY kyvzon_subscription_gate ... AS RESTRICTIVE
```

السياسات العادية تُجمع بـ`OR` — فإضافة واحدة قد **توسّع** الوصول. المقيِّدة تُجمع بـ`AND` فتضيّق فقط. اختبار يفشل إن صارت أي بوابة `PERMISSIVE`.

**308 بوابة أُضيفت، كلها `RESTRICTIVE`.**

## خطأ اكتشفه الحارس — لولاه لصمت السجل

كتبتُ الدالة `STABLE`، وPostgres يمنع الكتابة داخلها. البلوك `EXCEPTION` ابتلع الخطأ **صامتاً** فبدا أن التسجيل «لا يعمل» بلا سبب ظاهر.

حارس المايجريشن أمسكه: `0320 failed: audit mode did not log`. صُحِّحت إلى `VOLATILE`.

> لو لم أضع ذلك الحارس لكان وضع `audit` بلا فائدة — يمرّ ولا يسجّل — ولاكتُشف بعد التشغيل على عميل حقيقي.

## دليل التشغيل — شركة واحدة في كل مرة

### الخطوة ١: تقرير الأثر (قبل أي شيء)

```sql
SELECT * FROM public.preview_enforcement_impact('<tenant-uuid>');
```

يعطيك لكل وحدة: مسموحة؟ · كم صفاً فيها؟ · ملاحظة.

**اقرأ سطور `★ ستُمنَع ولديها N صف` بعناية** — هذه بيانات يستعملها العميل فعلاً.

### الخطوة ٢: وضع audit

```sql
SELECT public.set_module_enforcement('<tenant-uuid>', 'audit');
```

**اتركه أسبوعاً على الأقل** ليمرّ الاستعمال الشهري والدوري.

### الخطوة ٣: راجع السجل

```sql
SELECT * FROM public.enforcement_audit_summary();
```

| ما تراه | القرار |
|---|---|
| صفر محاولات | ✅ آمن للإقفال |
| محاولات لوحدة **يجب** أن يملكها | ⚠️ **أضِفها إلى `enabled_modules` أولاً** |
| محاولات لوحدة لا يملكها فعلاً | ✅ هذا بالضبط ما نريد منعه |

### الخطوة ٤: الإقفال

```sql
SELECT public.set_module_enforcement('<tenant-uuid>', 'enforce');
```

### التراجع الفوري

```sql
SELECT public.set_module_enforcement('<tenant-uuid>', 'off');
```

**أثره لحظي** — لا مايجريشن ولا إعادة نشر.

---

## توصيتي الصريحة

1. **ابدأ بشركة داخلية أو عميل صغير** — لا بأكبر عملائك
2. **راجع `enabled_modules` لكل شركة قبل audit** — القيمة الافتراضية `{employee}` غالباً غير صحيحة
3. **لا تُشغّل `enforce` على أكثر من شركة في اليوم** — لتبقى قادراً على ربط أي شكوى بسببها
