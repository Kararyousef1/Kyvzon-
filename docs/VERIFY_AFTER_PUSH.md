# دليل التحقق بعد `db push` — خطوة بخطوة

**التاريخ:** 2026-08-05 · **بعد تطبيق `0301`–`0316` على Supabase**

---

## أولاً: قراءة مخرجات `db push` — ما تعنيه فعلاً

| الرسالة | المعنى |
|---|---|
| `does not exist, skipping` | ✅ **طبيعي تماماً** — `DROP IF EXISTS` قبل الإنشاء. أول تطبيق فلا شيء ليُسقَط |
| `0302: رُحِّل 2 مدير قسم` | مديرا قسمين حصلا على وحدة الحركة تلقائياً |
| `0311: رُحِّل 1 إسناد حركة` | **ليس تناقضاً مع الرقم 2** — الاثنان نفس الشخص يدير قسمين، و`DISTINCT` يعطي صفاً واحداً |
| `0304: رُحِّل 6 إسناداً تنظيمياً` | من الأعمدة الأربعة القديمة إلى الجدول الجديد |

**ملاحظة:** `0300` لم يظهر في القائمة لأنه كان مُطبَّقاً في جولة سابقة. هذا صحيح.

## ثانياً: الفحص الآلي (٣٠ ثانية)

### الخطوة ١

افتح **لوحة Supabase ← SQL Editor ← New query**

### الخطوة ٢

الصق محتوى الملف كاملاً:

```
tools/dev/post-push-healthcheck.sql
```

> **للقراءة فقط** — لا يُنشئ ولا يُعدّل ولا يحذف أي صف. آمن على الإنتاج.

### الخطوة ٣ — اقرأ النتيجة

ستحصل على **١٦ سطراً**. المتوقَّع:

| المجال | الفحص | المتوقَّع |
|---|---|---|
| الجداول | الأربعة الجديدة | `4 / 4` ✅ |
| المحرك الموحّد | `unified_approvals` | موجود ✅ |
| الدوال | دوال المعمارية | `14 / 14` ✅ |
| أدوار التصنيع | دورة الحياة | `5 / 5` ✅ |
| أدوار التصنيع | الكتالوج | `9 / 9` ✅ |
| المحفّزات | المزامنة | `3 / 3` ✅ |
| الأمان | RLS مفعّلة | `4 / 4` ✅ |
| الأمان | `anon` محروم | محروم ✅ |
| الاتساق | الجسر متّسق | متّسق ✅ |
| الأمان | لا تصعيد للمشرف | سليم ✅ |
| التوافق الخلفي | أعمدة `departments` | `4 / 4` ✅ |

**التحذيرات ⚠️ الثلاثة طبيعية الآن:**
- «وحدات بوابة مُسنَدة» → سيصير رقماً بعد الإسناد اليدوي
- «أدوار تنظيمية مُرحَّلة» → عندك `6` من `0304`
- «قواعد اعتماد مُعرَّفة» → `0` حتى تُنشئها (الخطوة التالية)

**أي ❌ ⇒ أرسله لي فوراً مع نصّه.**

## ثالثاً: التحقق في المتصفح — ٦ سيناريوهات

### 🔍 سيناريو ١ — الشريط الجانبي للمدير (دقيقتان)

**الهدف:** التأكد أن الوحدات تظهر.

1. سجّل الدخول بحساب دوره **`manager`**
2. افتح قسم **«إدارة الفريق»** في الشريط

**المتوقَّع:** الصفحات الخمس القديمة + **وحدة الحركة — اعتماد التصاريح** و**حركة الفريق**

> ظهورها يعني أن `0302` رحّله كمدير قسم. إن لم تظهر ⇒ لم يُسنَد إليه ⇒ انتقل للسيناريو ٢.

---

### 🔍 سيناريو ٢ — إسناد وحدة (٣ دقائق)

**الهدف:** اختبار المعمارية الجديدة كاملة.

1. **الإدارة ← إدارة الموظفين ← عدّل مستخدماً**
2. الدور: **مدير**
3. **التالي ← التالي** (الخطوة الثالثة)
4. ستجد **«وحدات البوابة»** — أشّر على: **المالية** و**المخزون**
5. حدّد النطاق: **قسم** واختر قسماً
6. احفظ · سجّل خروج ودخول بذلك الحساب

**المتوقَّع:** ظهور «وحدة المالية — الاعتماد» و«وحدة المخزون — الاعتماد».

> ★ **الاختبار الحاسم:** دوره ما زال `manager` — لم يتحوّل إلى `finance_manager`. **هذا جوهر المعمارية الجديدة.**

---

### 🔍 سيناريو ٣ — الحارس يمنع غير المُسنَد (دقيقة)

بنفس الحساب، افتح يدوياً:

```
/app/manager/units/contracts/approvals
```

**المتوقَّع:** شاشة **«هذه الوحدة غير مُسنَدة إليك»** تشرح كيف يحصل عليها — لا صفحة بيضاء ولا خطأ.

---

### 🔍 سيناريو ٤ — قواعد الاعتماد ومسار الاعتماد (٥ دقائق)

**الهدف:** اختبار الاعتماد متعدد المستويات — أحدث ميزة.

1. **الإدارة ← التقارير ← قواعد الاعتماد**

   > إن لم تظهر في الشريط ⇒ أخبرني (كانت محجوبة قبل إصلاح هذه الجولة)

2. أنشئ **قاعدتين لنفس الوحدة**:

   | | القاعدة ١ | القاعدة ٢ |
   |---|---|---|
   | الوحدة | المالية | المالية |
   | المستوى | **1** | **2** |
   | الدور المطلوب | مدير | المدير المباشر |

3. **الإدارة ← الهيكل التنظيمي:** تأكد من إسناد الدورين لأشخاص

4. قدّم طلباً مالياً من بوابة المالية

5. ادخل بحساب **معتمِد المستوى الأول ← مركز الموافقات**

**المتوقَّع:**
- شارة بنفسجية **«مستوى 1 من 2»**
- زرّ **«مسار الاعتماد»** ← اضغطه

**المتوقَّع عند الفتح:**
```
① أنت (مدير)          بانتظار   ← وسم «الآن»
② فلان (مدير مباشر)   بانتظار
```

6. اضغط **موافقة**

**المتوقَّع:** رسالة **«اعتُمد مستواك — انتقل الطلب للمستوى التالي»** — ويختفي من صندوقك ويظهر عند الثاني.

---

### 🔍 سيناريو ٥ — أدوار التصنيع (٣ دقائق)

1. **الإدارة ← التقارير ← أدوار التصنيع الدقيقة**
2. **إسناد دور** ← اختر موظفاً ← **مشرف الإنتاج**

**المتوقَّع:** تنبيه برتقالي **«يُنصح بتحديد مصنع لهذا الدور»**

3. اختر مصنعاً (أو «كل المصانع» إن لم تسجّل مصانع) ← أسنِد
4. أسنِد **نفس الدور** لنفس الشخص في **مصنع آخر**

**المتوقَّع:** **إسنادان مستقلان** في بطاقته — لا واحد يستبدل الآخر

5. اسحب أحدهما ← أكّد

**المتوقَّع:** الآخر سليم · والمسحوب يظهر تحت **«عرض المسحوبة»** مشطوباً

---

### 🔍 سيناريو ٦ — بوابة المشرف (دقيقتان)

سجّل بحساب **`supervisor`**:

**المتوقَّع:** خمس وحدات كحدّ أقصى (الحركة · HR · المخزون · التصنيع · الصحة والسلامة)

**المتوقَّع ألّا يظهر:** المالية · المشتريات · العقود · CRM — **خارج نطاقه بالتصميم**

افتح **«وحدة الحركة — حركة الوردية»**:

**المتوقَّع:** يرى حركة ورديته **بلا زرّ اعتماد نهائي** — هذا مقصود لا نقص.

## رابعاً: ماذا ترسل لي

### إن ظهر ❌ في الفحص الآلي
انسخ السطر كاملاً.

### إن ظهر خطأ في المتصفح
1. **صورة الشاشة**
2. **رسالة الخطأ بنصّها الحرفي**
3. **Console** (F12 ← Console) — أي سطر أحمر
4. **Network** — الطلب الفاشل واسم الدالة

### إن كانت شاشة فارغة بلا خطأ
أخبرني **أي صفحة** و**دور المستخدم** — غالباً إسناد ناقص لا عطل.

## خامساً: ما لم يُختبر بعد — بصراحة

| البند | الحالة |
|---|---|
| كل ما سبق | ✅ Postgres محلي · اختبارات · بناء |
| **Supabase حقيقي** | 🟡 المايجريشنات طُبِّقت — **الدوال لم تُستدعَ من متصفح** |
| **٣٢ صفحة حركة** | ⬜ واحدة فقط رُئيت تعمل |
| **٥ واجهات جديدة** | ⬜ لم تُرَ إطلاقاً |

**السيناريوهات الستة أعلاه هي أول تشغيل حقيقي لهذه المعمارية.** توقّع أعطالاً — واكتشافها الآن هو الهدف.
