## القرار المعماري: صفحة واحدة بدل ست عشرة

الوحدات التسع × دورين = **16 صفحة موافقات محتملة**. نسخها يعني:

- 16 نسخة من نفس المنطق
- 16 فرصة للتباعد عند أي تعديل
- 16 صفحة تُختبر وتُصان

**لكن المحرك الموحّد (`0305`) يخدمها كلها أصلاً:**

```
my_approval_inbox(unitKey)      → طلبات هذه الوحدة لفريقي
unified_approval_decide(...)    → القرار يُوجَّه للجدول الصحيح
```

فالفرق بين «موافقات المشتريات» و«موافقات المخزون» **معامل واحد**، لا صفحة كاملة.

### النتيجة

| العنصر | العدد |
|---|---|
| صفحة عامة | **1** (`UnitApprovalsPage`) |
| حارس ديناميكي | **1** (`RequireDynamicPortalUnit`) |
| مسار | **2** (مدير · مشرف) |
| صفحات مُفعَّلة | **12** (8 مدير + 4 مشرف) |

### الاستثناء المتعمَّد

وحدة **الحركة** لها صفحتان مخصّصتان (اعتماد + تقرير فريق) لأن منظورها أغنى من قائمة موافقات. اختبار العقد يتحقق أنها **الوحيدة** بهذا الاستثناء:

```ts
const richer = PORTAL_UNITS.filter((u) => u.managerPages.length > 1);
expect(richer.map((u) => u.unitKey)).toEqual(['movement']);
```

فلو نسخ أحد صفحة لوحدة أخرى بلا مبرّر، يفشل الاختبار.

## التوزيع النهائي

### وحدات المدير — تسع

الحركة · الموارد البشرية · المالية · المشتريات · المخزون · التصنيع · العقود · المبيعات · الصحة والسلامة

### وحدات المشرف — خمس

الحركة · الموارد البشرية · المخزون · التصنيع · الصحة والسلامة

**لا مالية ولا مشتريات ولا عقود ولا CRM للمشرف** — خارج نطاقه، واختبار العقد يحرس ذلك.

نفس مبدأ `0307`: **المدير يعتمد · المشرف يتابع.**

## الحارس الديناميكي

`RequirePortalUnit` يأخذ `unitKey` ثابتاً. المسار الديناميكي `/units/:unitKey/approvals` يحتاج قراءته من المعامل — و**رفض المفاتيح غير المعروفة قبل أن تصل للقاعدة**:

```tsx
if (!unit || !unit.baseRoles.includes(baseRole)) {
  return <Card>وحدة غير معروفة</Card>;
}
```

الشرط الثاني مهم: يمنع المشرف من فتح `/app/supervisor/units/finance/approvals` — وحدة غير متاحة لدوره أصلاً.

### اختبار سلوكي عبر ثلاث وحدات

مدير على المالية والمشتريات والموارد البشرية، وثلاثة طلبات من بوابات مختلفة:

```
 out_source_module | out_unit_key |   out_title
-------------------+--------------+-------------
 finance           | finance      | مصروف
 procurement       | procurement  | طلب شراء
 general           | hr           | طلب إجازة
```

**والتصفية دقيقة:** `finance: 1` · `procurement: 1` · `hr: 1` · **`mrp: 0`** (غير مُسنَدة).

### اختبار العقد — 104 حالة

يفحص كل صفحة من الاثنتي عشرة في **خمسة** مواضع (Sidebar · Catalog · Admin · legacyRedirect · permissions)، ويتحقق من:

- تطابق `unit_key` بين الكتالوج والخرائط و**قيد القاعدة في `0302`**
- تطابق المسارات بين `legacyRedirect` و`path` في الكتالوج
- وسم صفحات المشرف بـ`supervisor` لا `manager` في `UNIT_PAGE_BASE_ROLE`

### إثبات كشف الانحدار

| العكس | النتيجة |

| منح المشرف صلاحية الاعتماد | × 🔴 المشرف لا يرى أزرار الاعتماد |

| وسم صفحة مشرف بـ`manager` | × صفحات المشرف موسومة supervisor |

### توضيح صريح

الوحدات الثماني تعرض **قائمة موافقات** فقط. وحدة الحركة وحدها لها تقرير فريق. إن أردت تقارير مخصّصة لكل وحدة فهذا عمل إضافي — لم يُنفَّذ ولا أدّعي غيره.
