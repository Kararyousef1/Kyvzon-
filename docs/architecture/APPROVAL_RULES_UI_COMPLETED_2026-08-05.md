## الرابع هو الأهم

> **قاعدة اعتماد خاطئة أخطر من غيابها** — لأن الطلب يقع في فراغ صامت.

الكاشف يرصد أربع حالات:

| الحالة | الخطورة | مثال من الاختبار الفعلي |
|---|---|---|
| **نطاقان متداخلان** | `error` | «قاعدة أ» (0–5000) تتداخل مع «قاعدة ب» (3000–8000) في المستوى 1 |
| **فجوة بين نطاقين** | `warning` | لا قاعدة بين 1000 و 5000 — طلب بهذا المبلغ بلا معتمِد |
| **دور بلا شاغل** | `error` | «تسوية» تطلب دور direct_manager في قسم العمليات — لا أحد يشغله |
| **وحدة بلا قواعد** | `info` | تعتمد على السلسلة التنظيمية وحدها |

والرسائل تذكر **الأسماء والأرقام** لا مجرد «يوجد تعارض».

### الاختبار الحاسم

```
22 | ✅ يكشف دوراً مطلوباً بلا شاغل        | count=1
23 | ✅ الإنذار يختفي بعد إسناد الدور      | count=0
```

الكاشف **يتفاعل مع الهيكل التنظيمي حياً**: تُسند الدور فيختفي الإنذار.

وفي المقابل:

```
20 | ✅ القواعد المتتالية السليمة بلا إنذار | issues=0
```

فلا إنذارات كاذبة.

## الشاشة: الفجوات قبل القائمة

لوحة الفجوات **أعلى الصفحة عمداً** — المستخدم يرى المشكلة قبل الجدول. واختبار العقد يفرض الترتيب:

```ts
const gapsIdx = PAGE.indexOf('gaps.map');
const tableIdx = PAGE.indexOf('<table');
expect(gapsIdx).toBeLessThan(tableIdx);
```

وعند سلامة القواعد: شريط أخضر «لا فجوات ولا تعارضات».

## ⚠️ خطأان صحّحتُهما

**١. إنذار تسرّب كاذب.** اختبار «لا قاعدة تعبر حدود المستأجر» فشل بـ`cross=1`. الفحص أثبت أن القاعدة في المستأجر **الصحيح** — والتسرّب وهمي: اختباري كان يفحص بالاسم فالتقط بقايا مستأجر من تشغيلي اليدوي السابق. أصلحتُه ليفحص عبر اللوحة المفلترة بالمستأجر، وأضفتُ تأكيداً معاكساً.

**٢. اختبار لا يعمل أصلاً.** استيراد `ApprovalRulesService` يُهيّئ عميل Supabase فيفشل بلا متغيّرات بيئة — `no tests`. اتبعتُ نمط بقية الاختبارات: قراءة الملف نصّاً واستخراج التسميات. **وهذا أصحّ أيضاً** لأنه يفحص الملف الحقيقي لا نسخة مستوردة.
