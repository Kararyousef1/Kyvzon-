**لم يُنفَّذ `git push` ولا `db push`**

## ملخّص

الجولة السابقة بنت الشاشة لكنها تُسنِد بنطاق «كل المصانع» فقط. هذه الجولة تُتيح اختيار المصنع — وتكشف **عدم اتساق امتيازي** كان سيُنتج قائمة فارغة بلا تفسير.

```
244 مايجريشن من الصفر         صفر فشل
675 تأكيداً سلوكياً · 23/24 ملف   (الفاشل أداة سحابة لا اختبار)
1999/1999 اختبار وحدة · 111 ملفات
tsc EXIT=0 · lint 0 خطأ · build ✅ · contract-check PASS
sdk:boundary-check: صفر انتهاك في ملفاتي
```

## ★ العطل: امتيازان لا يعرف أحدهما الآخر

`0314` عرّف `can_manage_mrp_roles()` فمنح الامتياز لحامل وحدة `mrp` **ولو كان `profiles.role = 'employee'`** — وهذا مقصود: ربط الامتياز بالمعمارية الجديدة (`0302`) لا بالدور الخام.

لكن RLS على `manufacturing_plants` من `0218`:

```sql
current_user_role() = ANY (ARRAY['manufacturing','manager','admin','developer','it_admin'])
```

**مُثبَت بمسبار على قاعدة حقيقية:**

```
can_manage_mrp_roles() = TRUE   ⇒ الشاشة تُفتح
SELECT من manufacturing_plants  ⇒ صفر صفوف
```

المستخدم يرى شاشة إسناد الأدوار وقائمة المصانع فارغة بلا تفسير — **أسوأ من المنع الصريح**. وهو نفس مرض المشروع المعالَج منذ `0302`: مصدران للحقيقة لا يعرف أحدهما الآخر.

### الحل: دالة واحدة تحمل الامتياز نفسه

| | |
|---|---|
| ❌ توسيع RLS على `manufacturing_plants` | يفتح الجدول كاملاً (إنشاء · تعديل · أرشفة) لمن نريد له قراءة الأسماء فقط |
| ✅ `mrp_plants_for_role_scope()` | `SECURITY DEFINER` بحارس `can_manage_mrp_roles()` صريح · **ثلاثة أعمدة فقط** |

اختبار العقد يحرس المبدأ: يفشل إن ظهر `DROP POLICY` أو `ALTER TABLE public.manufacturing_plants` في المايجريشن.

## ★ التوسعة الثانية: إرشاد التنطيق

ليست كل الأدوار التسعة منطقيّة على مستوى المصنع. `mrp_role_catalog()` صار يعيد عموداً ثالثاً `out_plant_scoped`:

| على مستوى الشركة (3) | ميداني — يُنصح بتنطيقه (6) |
|---|---|
| مخطّط الإنتاج · مهندس قوائم المواد · محاسب التكاليف | مدير الإنتاج · مشرف الإنتاج · مشغّل أرضية المصنع · مفتّش الجودة · فني الصيانة · مدير الصيانة |

**إرشاد لا قيد.** القاعدة تقبل أي تركيبة — فرض القيد سيكسر حالات مشروعة (شركة بمصنع واحد تريد تنطيق كل شيء). الشاشة تعرض تنبيهاً برتقالياً عند اختيار دور ميداني، لا أكثر.

## سلوك النطاق — مُثبَت تشغيلياً

نفس الدور في مصنعين **إسنادان مستقلان**، والنطاق العام ثالث مستقل:

```
production_supervisor @ مصنع بغداد   ⎫
production_supervisor @ مصنع البصرة  ⎬ ثلاثة صفوف
production_supervisor @ كل المصانع   ⎭

revoke(…, مصنع بغداد) ⇒ 1 صف   · الآخران سليمان
```

وقد اختبرتُ الأربعة صراحةً: التكرار بنفس المصنع لا يُنشئ صفاً رابعاً، وسحب مصنع لا يمسّ الآخر ولا النطاق العام.

## أخطاء اكتشفتُها هذه الجولة وصحّحتُها

| # | الخطأ | كيف انكشف | التصحيح |
|---|---|---|---|
| ١ | استعملتُ `status='archived'` في الاختبار — القيد يقبل `active·inactive·closed` فقط | **تشغيل الاختبار** | صُحِّح إلى `closed` + تأكيد يمنع عودة `archived` |
| ٢ | تأكيد 1.3 كان `v_n >= 0` — **صحيح دائماً** فتأكيد ميت. الاختبار يعمل بدور `postgres` (BYPASSRLS) فأي `SELECT` مباشر يمرّ | مراجعة ذاتية | حُذف وكُتب مكانه تعليق يشرح لماذا لا يُفحص هنا — **لا نُوثّق ما لم نُثبته** |
| ٣ | غيّرتُ نوع إرجاع `mrp_role_catalog` فقد يكسر `0314` | فحص استباقي | أُثبت بإعادة تشغيل `0314` بعد `0315` ثم اختباره السلوكي — 36/36 |

هذا ثالث «تأكيد ميت» أكتشفه في ثلاث جولات (`OR TRUE` · نافذة فضفاضة · `>= 0`). الصنف متكرر بما يكفي ليستحق انتباهاً دائماً.

## خطوتك

```bash
npx supabase db push
```

ثم: **الإدارة ← التقارير ← أدوار التصنيع الدقيقة ← إسناد دور**

1. اختر «مشرف الإنتاج» — يظهر تنبيه برتقالي «يُنصح بتحديد مصنع»
2. اختر مصنعاً وأسنِد
3. أسنِد الدور نفسه في مصنع آخر — إسنادان مستقلان في البطاقة
4. اسحب أحدهما — الآخر سليم

**إن لم تكن هناك مصانع مسجَّلة**، تظهر رسالة «لا مصانع مسجَّلة — سيُسنَد على كل المصانع» بدل قائمة فارغة صامتة.
