## `0304` — الهيكل التنظيمي: صفوف بدل أعمدة

### المشكلة

`departments` تحمل أربعة أعمدة: `manager_id` · `supervisor_id` · `direct_manager_id` · **`procurement_manager_id`**.

الرابع هو **الدليل الحاسم**: بوابة المشتريات احتاجت «مدير مشتريات للقسم» فأُضيف لها عمود خاص. ولو تابعنا لصار في الجدول عمود لكل بوابة.

### الحل

```sql
org_role_assignments (department_id, org_role, unit_key, user_id)
-- org_role ∈ supervisor · manager · direct_manager · unit_manager
```

**إضافة دور جديد = صف، لا `ALTER TABLE`.**

### التوافق الخلفي مطلق

| الالتزام | التنفيذ |
|---|---|
| لا حذف أعمدة | حارس يتأكد من بقاء الأربعة |
| لا مسّ `resolve_department_chain` (0153) | حارس صريح — بوابة HR تعتمدها |
| ترحيل نسخاً لا نقلاً | حارسا مطابقة |
| مزامنة حيّة | محفّز **باتجاه واحد** (عمود ← صف) لتفادي حلقة المحفّزات |

**الاختبار 24 هو الحاسم:** الدالة القديمة والجديدة تُرجعان **نفس المدير** — التوافق مُثبَت لا مُدَّعى.

### الوراثة

```
التطوير (الأعمق)
  supervisor     → من القسم نفسه   (inherited=false)
  manager        → من التقنية      (inherited=true)
  direct_manager → من الشركة       (inherited=true)
```

والمشرف **لا يُورَث للأعلى** — مطابقةً لمنطق `0153`.

## `0305` — محرك الموافقات: مركز واحد

### الاكتشاف الذي غيّر كل شيء

```
approval_requests → مايجريشن INSERT: 0 · SDK INSERT: 0
```

`ManagerApprovalsPage` (17 سطراً) كان يقرأ هذا الجدول وحده. **لا أحد يكتب فيه منذ 0023.** الصفحة كانت فارغة **أبداً** — لا عرضاً.

### القرار المعماري

**رفضتُ** ترحيل التسعة إلى جدول واحد: يمسّ تسع بوابات في الإنتاج بمخاطرة هائلة.

**المختار:** طبقة فوقها — بلا لمس أي جدول:

```sql
CREATE VIEW unified_approvals AS
  SELECT 'hr', ... FROM hr_approval_requests WHERE status='pending'
  UNION ALL ... -- التسعة
```

الفروق البنيوية تُطبَّع في العرض: بعضها `status` وبعضها `decision`، بعضها بمبلغ وبعضها بلا.

### الحماية بطبقتين

```sql
IF NOT public.has_portal_unit('manager', v_unit) THEN
  RAISE EXCEPTION 'NOT_ASSIGNED_TO_UNIT (manager/%)', v_unit;
END IF;
IF v_requester IS NOT NULL AND NOT public.is_in_my_team(v_requester) THEN
  RAISE EXCEPTION 'REQUESTER_NOT_IN_MY_TEAM';
END IF;
```

**قبل** أي `UPDATE` — اختبار العقد يتحقق من الترتيب.

### النتيجة المرئية

```
 out_source_module |    out_title    | out_requester_name | out_amount
-------------------+-----------------+--------------------+-----------
 movement          | تصريح خروج      | موظف               |
 procurement       | طلب شراء        | موظف               |   5000.00
```

**طلب حركة وطلب شراء في مكان واحد.** هذا جوهر فكرتك محقَّقاً.

## خطوتك

```bash
npx supabase db push
```

ثم افتح **بوابة المدير ← مركز الموافقات**. توقّع:

- **بلا وحدات:** «لم تُسنَد إليك وحدات بعد»
- **بوحدات:** كل الطلبات المعلَّقة من وحداتك، بشارة ملوّنة لكل بوابة
- **تصفية** بالوحدة إن كان لك أكثر من واحدة
- **زر موافقة/رفض** بنافذة حوار (لا `prompt`)

**اختبار العزل:** أنشئ طلباً من قسم آخر وتأكد أنه **لا يظهر**.
