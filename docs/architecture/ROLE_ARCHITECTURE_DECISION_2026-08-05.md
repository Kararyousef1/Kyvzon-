## الجزء الأول: `movement_manager`

### التشخيص — ليس دوراً، بل اختصار كتابي

| المصدر | `employee_movement` | `logistics` | `movement_manager` | الاتحاد |
|---|---:|---:|---:|---|
| `hybridPagesCatalog.ts` | 7 | 15 | **22** | **22** — تطابق تام |
| `Sidebar.tsx` | 7 | 15 | **22** | **22** — تطابق تام |
| `permissions.ts` | 11 | 19 | **28** | 26 + `reports` + `analytics` |

بصمته التنفيذية في القاعدة **9 أسطر** من أصل 111 إشارة. و`movement_require_role()` **لا يقبله معاملاً أصلاً**:

```sql
-- 0282:108
IF p_role NOT IN ('employee_movement', 'logistics') THEN
  RAISE EXCEPTION 'INVALID_MOVEMENT_ROLE (%)', p_role;
```

الاستدعاءات الـ37: **34 بـ`logistics` · 3 بـ`employee_movement` · صفر بـ`movement_manager`**.

### ★ العطل الجوهري — مُثبَت تشغيلياً

```
INSERT profiles(role='manager')                    ⇒ إسنادات حركة = 0  ✅ متوقَّع
INSERT portal_unit_assignments(manager, movement)  ⇒ إسنادات حركة = 0  ❌ العطل
```

المزامنة كانت **باتجاه واحد**:

```
0300:  profiles.role ──────────────► movement_role_assignments
0302:  portal_unit_assignments ────► (لا شيء)              ← الفجوة
```

**الأثر:** لمنح مدير صلاحية الحركة كان لا بد من تغيير `profiles.role` إلى `movement_manager` — فيفقد دوره `manager` وبوابة المدير كاملةً، لأن `profiles.role` عمود واحد. **استحالة الجمع بين الدورين هي بعينها المشكلة.**

### القرار: (ج) جسر — ولماذا لا (أ) ولا (ب)

| | (أ) تجميد | (ب) هجرة كاملة | **(ج) جسر** |
|---|---|---|---|
| العمل | إصلاح المسار فقط | 9 أسطر SQL + 60 موضع TS | مايجريشن واحد |
| الخطر | التناقض يعود مع كل بوابة | تكسر 34 استدعاءً فوراً | منخفض |
| نهاية الدور | أبداً | فوراً (كسر) | يموت مع البوابة القديمة |

(ج) هو المكافئ المعماري لقرارك السابق «إيقاف تدريجي للبوابة القديمة».

### `0311` — ما نُفِّذ

```
portal_unit_assignments(manager, movement) ──► movement_role_assignments(origin='unit_sync')
```

ثلاثة مصادر لا يتداخل أحدها مع الآخر:

| `origin` | يملكه | لا يمسّه |
|---|---|---|
| `manual` | الإنسان | أي محفّز |
| `profile_sync` | `0300` | `0311` |
| `unit_sync` | `0311` | `0300` |

**قرار أمني صريح: المشرف لا يُجسَّر.** أصغر دور في البوابة القديمة (`employee_movement`) يفتح 7 صفحات فيها اعتماد التصاريح وإدارة السياسات، بينما المشرف — بنص فلسفة `0307` — «يتابع ولا يعتمد نهائياً». جسرُه تصعيدُ امتياز صامت.

**النتيجة المُثبَتة:**

```
profiles.role = manager  ⇒ بوابة المدير سليمة + بوابة الحركة مفتوحة معاً
```

### ★ الاكتشاف الذي غيّر التشخيص

`0218` أنشأ جدول `mrp_user_roles` بعمود `manufacturing_role` يقبل **هذه الأدوار بالضبط**، وله RLS وسياستان. لكنه **يتيم تماماً**:

```sql
SELECT proname FROM pg_proc WHERE prosrc ILIKE '%mrp_user_roles%';   ⇒ 0 صف
SELECT count(*) FROM pg_policies WHERE qual ILIKE '%mrp_user_roles%'; ⇒ 0
```

و`mrp_require_roles` يقرأ `profiles.role` وحده. مسبار مباشر:

```
صف mrp_user_roles موجود = 1
لكن current_user_role() = employee   ⇒ يُرفض رغم إسناده
⇒ 99 استدعاءً تذكر production_manager = فروع ميتة
```

**الأثر:** كل صلاحيات التصنيع الدقيقة تنهار إلى صلاحية خشنة واحدة `manufacturing`. مخطِّط الإنتاج ومهندس BOM ومفتّش الجودة — كلهم إما `manufacturing` بكل الصلاحيات أو لا شيء. **عكس مبدأ أقل امتياز.**

### القرار: تفعيل الجدول القائم

- ❌ حذف الـ388 استدعاءً — يُلغي تصميماً مقصوداً ويوسّع الصلاحيات
- ❌ إضافة 11 دوراً لـ`profiles.role` — انفجار أدوار صريح؛ ودور واحد لكل مستخدم يعني أن مدير الإنتاج يفقد `manufacturing`
- ✅ **تفعيل `mrp_user_roles`** — الجدول مصمَّم لهذا ويسمح بأدوار متعددة

وهذا **نفس نمط Scoped Roles** المعتمد في `0302`: دور خشن في `profiles` + أدوار دقيقة بنطاق في جدول مخصص. **نُعمّم النمط لا نخترع غيره.**

### النتيجة المُثبَتة

```
profiles.role            = employee
current_user_mrp_roles() = {production_manager}
✅ مدير الإنتاج يمرّ — 99 فرعاً ميتاً أُحييت
✅ يُرفض على bom_engineer — أقل امتياز محفوظ
✅ توافق خلفي: manufacturing ما زال يمرّ على كل شيء
```

## الجزء الثالث: حلقة إعادة توجيه لا نهائية

`ROLE_DEFAULT_PATH` حوى 15 دوراً من 18. الناقصون: أدوار الحركة الثلاثة.

```
1. getDefaultPathForRole('movement_manager') → لا مفتاح → '/app/employee'
2. AppRouter:1177  <Route path="employee" roles={['employee','supervisor','manager']}>
3. RequireRole:34  الدور ليس في القائمة → Navigate(getDefaultPathForRole(...))
4. → '/app/employee' → عُد إلى 2 … بلا نهاية
```

**لماذا لم يُكشف:** الاختبار فحص ثمانية أدوار مكتوبة يدوياً. أُعيدت كتابته ليشتقّ القائمة من نص `export type UserRole`.

**برهان قاطع** — على الشيفرة المعطوبة نفسها:

| | الاختبار القديم | الاختبار الجديد |
|---|---|---|
| النتيجة | **1 passed** ✅ | **4 failed** ❌ |

## الجزء الرابع: ★ انحدار في عملي السابق — تصحيح علني

`0301` (جولتي السابقة) أضاف قيد `logistics_drivers_type_employee_coherence` لكنه **لم يُحدِّث** `create_fleet_driver` — المسار الوحيد لإنشاء سائق. الدالة تُدرج بلا `driver_type` فيأخذ الافتراضي `'employee'` بينما `p_employee_id` افتراضيه `NULL`:

```
ERROR: new row for relation "logistics_drivers" violates check constraint
       "logistics_drivers_type_employee_coherence"
```

**كل إنشاء سائق متعاقد كان يفشل** — أي أن قرارك الصريح «السائق موظف ومتعاقد معاً» كان مكسوراً في نصفه الثاني منذ `0301`.

**لماذا لم يكشفه حارس `0301`:** فحص **وجود** القيد لا **توافق الدوال معه**. `0313` يشتقّ `driver_type` من `employee_id` فيستحيل بناءً إنتاج صف مخالف.
