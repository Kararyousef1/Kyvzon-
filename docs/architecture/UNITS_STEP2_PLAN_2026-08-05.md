# معمارية الوحدات — خطة الخطوة ٢

**التاريخ:** 2026-08-05 · **الحالة:** خطة قبل التنفيذ

---

## الهدف

واجهة إسناد الوحدات في **الخطوة ٣** من معالج إدارة المستخدمين — فتُغني عن SQL اليدوي وتكمل الدورة.

عند اختيار الدور **مدير** أو **مشرف**، تظهر بطاقات الوحدات مع اختيار النطاق.

---

## ما وجدتُه في المراجعة

### ✅ جاهز

| العنصر | الحالة |
|---|---|
| `form.department_id` | موجود في النموذج ويُملأ عند اختيار القسم (سطر 1311) |
| `form.branch_id` | موجود ويُملأ |
| `departments` · `branches` | مُحمَّلة في الصفحة |
| `newUserId` | متاح بعد الإنشاء (سطر 932) — نقطة الإسناد |
| `portalUnitService.syncUserUnits` | جاهز من الخطوة ١ |

### 🔴 عائقان اكتشفتهما

**العائق ١ — `openEdit` يمسح `department_id`:**

```ts
// سطر 775
department_id: '',   // ← دائماً فارغ عند التحرير
```

يُملأ فقط عند تغيير القسم يدوياً في الخطوة ٢. فمدير موجود نفتح تعديله ونُسند له وحدة بنطاق «قسمه» ⇒ `scope_id` فارغ ⇒ **يفشل قيد `portal_unit_scope_coherence`**.

**الإصلاح:** استنتاج `department_id` من `emp.department` بمطابقة الاسم — نفس منطق الجسر في `is_in_my_team`.

**العائق ٢ — `handleSave` لا يعرف الوحدات:**

يكتب `entity_memberships` للمالية (سطر 887) لكن لا شيء لـ`portal_unit_assignments`. نضيف المزامنة في مسارَي الإنشاء والتحرير.

## التصميم

### حالة جديدة في النموذج

```ts
portal_units: [] as Array<{
  unitKey: PortalUnitKey;
  scopeType: PortalUnitScopeType;
  scopeId: string | null;
}>
```

### مكوّن `PortalUnitPicker`

مكوّن مستقل (لا نُضخّم `AdminEmployeesPage` الذي تجاوز 1500 سطر):

```
src/pages/admin/components/PortalUnitPicker.tsx
```

**سلوكه:**
- يظهر **فقط** إذا كان الدور `manager` أو `supervisor`
- بطاقة لكل وحدة من `unitsForBaseRole(role)`
- الوحدات `planned` معطَّلة بوسم «قريباً» — **لا وعد كاذب**
- عند اختيار وحدة: قائمة النطاق (قسم · فرع · الشركة)
- النطاق الافتراضي = قسم الموظف إن وُجد، وإلا «الشركة»
- تحذير مرئي عند اختيار «الشركة كاملة»

### التكامل مع `allowed_pages`

الوحدة تُنتج صفحاتها تلقائياً في `allowed_pages` — لا تُبدّله. فمن يُسنَد له وحدة الحركة تُضاف صفحتاها، ومن تُنزع منه تُزال.

## نطاق العمل

| # | العنصر | التفصيل |
|---|---|---|
| ١ | `PortalUnitPicker.tsx` | مكوّن البطاقات + اختيار النطاق |
| ٢ | `AdminEmployeesPage` — حالة | `portal_units` في `EMPTY_FORM` |
| ٣ | `openEdit` | استنتاج `department_id` + تحميل الوحدات القائمة |
| ٤ | `handleSave` | مزامنة الوحدات في المسارين |
| ٥ | الخطوة ٣ | إدراج المكوّن قبل قسم الصفحات |
| ٦ | `allowed_pages` | إضافة/إزالة صفحات الوحدة تلقائياً |
| ٧ | اختبارات | عقد + سلوكي على Postgres |

### ما **لن** أفعله

- ❌ لا ألمس `movement_manager`
- ❌ لا أبني وحدات جديدة (الحركة وحدها نشطة)
- ❌ لا أوحّد جداول الموافقات
- ❌ لا أُصلح `prompt()` في `ManagerApprovalsPage` (خطوة لاحقة — خارج النطاق)

## المخاطر

| الخطر | التخفيف |
|---|---|
| `department_id` فارغ ⇒ فشل القيد | استنتاج بالاسم + منع اختيار «قسم» بلا قسم |
| تغيير الدور من مدير لموظف | الوحدات تُعطَّل تلقائياً (`syncUserUnits` بلا حذف) |
| تضخّم `AdminEmployeesPage` | مكوّن مستقل |
| فشل المزامنة يُفشل الحفظ كله | معالجة منفصلة مع رسالة واضحة |
