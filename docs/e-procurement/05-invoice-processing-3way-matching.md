## أولاً: مفهوم المطابقة الثلاثية (3-Way Matching)

### الوثائق الثلاث التي تُطابَق

```
الوثيقة 1: أمر الشراء (Purchase Order)
"ما اتفقنا على شرائه وبأي سعر"
    ↕ مطابقة
الوثيقة 2: وثيقة استلام البضائع (Goods Receipt)
"ما وصلنا فعلاً وبأي كمية"
    ↕ مطابقة
الوثيقة 3: فاتورة المورد (Vendor Invoice)
"ما يطالبنا المورد بدفعه"

الثلاثة تتطابق؟
  ✅ نعم → اعتماد الدفع تلقائياً
  ❌ لا  → تعليق + تحقيق
```

### ما يُطابَق تحديداً في كل سطر؟

| المعيار | PO | GR | الفاتورة | يجب أن |
|---------|----|----|---------|--------|
| رقم الصنف | RM-001-STEEL | RM-001-STEEL | RM-001-STEEL | يتطابق تماماً |
| الكمية | 600 KG | 598 KG | 598 KG | الفاتورة = GR |
| السعر/وحدة | 42.00 ريال | — | 42.00 ريال | الفاتورة = PO |
| الإجمالي | 25,200 ريال | — | 25,116 ريال | محسوب صحيح |
| الضريبة | 15% | — | 15% | حسب القانون |

## ثانياً: المطابقة الثنائية مقابل الثلاثية

### المطابقة الثنائية (2-Way Match)
تُطابق فقط PO مع الفاتورة — بدون التحقق من الاستلام الفعلي.

```
متى تُستخدم؟
  - الخدمات المتكررة (إيجار، اشتراكات، خدمات مهنية)
  - حيث لا توجد "بضاعة" مادية للاستلام
  - الشراء الإلكتروني الفوري (SaaS، تراخيص)

المخاطر:
  - لا تحقق من التسليم الفعلي
  - مناسبة فقط للموردين ذوي السمعة العالية
```

### المطابقة الرباعية (4-Way Match)
تُضيف وثيقة رابعة: تقرير الفحص (Inspection Report) من الجودة.

```
متى تُستخدم؟
  - المواد الحرجة والغالية (فئة A في تحليل ABC)
  - الصناعات الدوائية والغذائية وذات التنظيم الصارم
  - الأصول الرأسمالية الكبيرة
```

## ثالثاً: سير معالجة الفاتورة الكاملة

### الخطوة 1: استلام الفاتورة (Invoice Receipt)

**قنوات الاستلام:**
```
القناة 1: البريد الإلكتروني
  المورد يرسل PDF للبريد الرسمي للفواتير
  → OCR يستخرج البيانات تلقائياً
  → يُنشئ فاتورة في النظام للمراجعة

القناة 2: بوابة الموردين
  المورد يرفع الفاتورة مباشرة في البوابة
  → البيانات مُدخلة رقمياً من البداية (لا OCR)
  → أعلى دقة وأسرع معالجة

القناة 3: EDI (التبادل الإلكتروني للبيانات)
  للموردين الكبار — الفواتير تصل برمجياً
  → تكامل مباشر بين نظام المورد ونظام Kyvzon

القناة 4: البريد التقليدي
  فاتورة ورقية → مسح ضوئي + OCR
  → الأبطأ والأعلى تكلفة — يُشجَّع التحول الرقمي
```

### الخطوة 2: استخراج البيانات (Data Extraction)

```
OCR + AI يستخرجان تلقائياً:
  □ رقم الفاتورة: INV-KH-2026-4471
  □ تاريخ الفاتورة: 29 يوليو 2026
  □ اسم المورد: شركة الخليج للمواد الصناعية
  □ رقم PO المذكور: PO-2026-01847
  □ المبلغ قبل الضريبة: 25,116 ريال
  □ الضريبة 15%: 3,767 ريال
  □ الإجمالي: 28,883 ريال
  □ رقم الحساب البنكي: SA44 2000 0001 2345 6789 0123

دقة AI في الاستخراج: 95-98%
الحقول المتبقية تُراجَع يدوياً
```

### الخطوة 3: تشغيل المطابقة التلقائية

<cite index="45-1">عند تقديم الفاتورة، يُطابقها النظام تلقائياً مع أمر الشراء وإيصال الاستلام. الانحرافات تُعلَم فوراً، ويمكن تكوين سير العمل لتوجيه الاستثناءات للمراجعة أو تصعيدها للشخص المناسب.</cite>

```
النظام يُشغّل المطابقة:

البند 1 — صفيحة فولاذ:
  PO:          600 KG × 42.00 = 25,200 ريال
  GR:          598 KG (استلمنا 598 فقط)
  الفاتورة:    598 KG × 42.00 = 25,116 ريال

  الكمية:  598 = 598 ✅
  السعر:   42.00 = 42.00 ✅
  الإجمالي: 25,116 = 25,116 ✅
  الحالة: ✅ مطابق

البند 2 — مرشح زيت:
  PO:          5 قطع × 185 = 925 ريال
  GR:          5 قطع
  الفاتورة:    5 قطع × 190 = 950 ريال

  الكمية:  5 = 5 ✅
  السعر:   185 ≠ 190 ❌ (فرق 5 ريال/قطعة = 25 ريال)
  الحالة: ❌ تعارض في السعر — يحتاج مراجعة

النتيجة الإجمالية: انحراف في السعر → يُعلَّق الدفع
```

### الخطوة 4: معالجة الاستثناءات (Exception Handling)

```
أنواع الاستثناءات وكيف تُعالَج:

الاستثناء 1: فرق في السعر
  → البحث: هل PO تم تعديله؟ هل هناك اتفاقية سعر أحدث؟
  → التواصل مع المورد لمعرفة سبب الفرق
  → إذا خطأ من المورد: يُرسَل Credit Note أو فاتورة معدّلة
  → إذا تغير السعر باتفاق: PO يُعدَّل → مطابقة جديدة

الاستثناء 2: فرق في الكمية (المفوتَر أكثر مما استلمنا)
  → الفاتورة صادرة بـ 600 KG لكننا استلمنا 598 KG
  → اتصال بالمورد: "فاتورتكم بـ 600 لكننا استلمنا 598"
  → تعديل الفاتورة أو إصدار Credit Note بـ 2 KG

الاستثناء 3: فاتورة بدون PO
  → ترفض تلقائياً أو تذهب لمسار موافقة خاصة
  → مدير المشتريات يُحقق: هل شراء مُسرَّب؟

الاستثناء 4: فاتورة مكررة (Duplicate)
  → نفس رقم الفاتورة أو نفس المبلغ لنفس المورد في تاريخ متقارب
  → تُعلَم فوراً كـ "مشبوهة بالتكرار"
  → تحقيق قبل أي دفع
```

## رابعاً: حدود التسامح (Tolerance Thresholds)

ليس كل فرق صغير يستحق تأخير الدفع. الحدود تُحدد متى يُقبل الاختلاف تلقائياً:

```
حدود التسامح الموصى بها:
  فرق السعر:
    حتى 0.5% من سعر البند → موافقة تلقائية مع تسجيل
    0.5% - 2%:    → موافقة موظف AP
    فوق 2%:        → موافقة مدير المشتريات
    فوق 5%:        → موافقة المدير المالي

  فرق الكمية:
    حتى 0.5% (هالك طبيعي في الشحن) → قبول تلقائي
    0.5% - 2%:    → موافقة موظف AP
    فوق 2%:        → تحقيق واتصال بالمورد

مثال عملي:
  PO: 600 KG × 42.00 = 25,200 ريال
  الفاتورة: 600 KG × 42.18 = 25,308 ريال
  الفرق: 108 ريال (0.43%)
  → ضمن حد التسامح 0.5% → موافقة تلقائية مع تسجيل
```

## خامساً: سير اعتماد الدفع

```
فاتورة مطابقة كاملاً:
  → اعتماد دفع تلقائي في تاريخ الاستحقاق (بدون تدخل بشري)

فاتورة باستثناء صغير (ضمن حد التسامح):
  → موظف AP يراجع ويعتمد

فاتورة باستثناء متوسط:
  → مدير المشتريات يراجع ويعتمد

فاتورة بانحراف كبير:
  → المدير المالي يراجع ويعتمد

فاتورة بدون PO أو مشبوهة:
  → لجنة مراجعة (مشتريات + مالية)
```

## سادساً: إدارة شروط الدفع والتحسين المالي

### Early Payment Discounts (خصومات الدفع المبكر)
```
شروط النص: "2/10 Net 45"
المعنى: خصم 2% إذا دُفع خلال 10 أيام، وإلا المبلغ كاملاً خلال 45 يوم

حساب الفائدة الفعلية على الخصم:
  الخصم 2% لتوفير 35 يوم (45-10)
  معدل الفائدة الفعلية = (2% / 98%) × (365 / 35) = 21.3% سنوياً!

القرار: إذا لم يكن تكلفة رأس المال > 21.3%، ادفع مبكراً واستفد من الخصم
```

### Dynamic Discounting (الخصم الديناميكي)
المورد يختار: هل يريد المال الآن بخصم أصغر أم ينتظر الموعد؟

```
الفاتورة: 100,000 ريال — مستحقة بعد 45 يوم
المورد يحتاج السيولة الآن:
  الدفع اليوم: 98,500 ريال (خصم 1.5%)
  الدفع بعد 20 يوم: 99,200 ريال (خصم 0.8%)
  الدفع بعد 45 يوم: 100,000 ريال (بدون خصم)

Kyvzon يختار: يدفع اليوم ويوفر 1,500 ريال
المورد يقبل: يحصل على سيولة فورية
كلاهما يربح
```

## ثامناً: مؤشرات الأداء

| المؤشر | التعريف | الهدف |
|--------|---------|-------|
| Straight-Through Processing (STP) | فواتير مطابقة تلقائياً بدون تدخل | 85%+ |
| متوسط وقت معالجة الفاتورة | من الاستلام للاعتماد (أيام) | أقل من 2 يوم |
| معدل الفواتير المتنازع عليها | فواتير مرفوضة أو معدّلة / إجمالي | أقل من 5% |
| معدل الدفعات في الموعد | دفعات في الموعد / إجمالي الدفعات | 98%+ |
| توفير خصومات الدفع المبكر | قيمة الخصومات المستفاد منها | تعظيم |
| اكتشاف الفواتير المكررة | مكررة مُحتجَزة / إجمالي الفواتير | تتبع |
| تكلفة معالجة الفاتورة الواحدة | إجمالي تكاليف قسم AP / عدد الفواتير | تقليل |

## تاسعاً: ما يجب أن تتضمنه هذه الوحدة في Kyvzon

- **استلام الفواتير متعدد القنوات:** بريد + بوابة موردين + EDI

- **لوحة تحليلات:** STP Rate، وقت المعالجة، اكتشاف الأنماط
