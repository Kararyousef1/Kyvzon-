## لماذا الاستلام هو "بوابة الحقيقة" للمستودع؟

<cite index="11-1">معظم مشاكل الإتمام لا تبدأ عند محطة التعبئة أو رصيف الشحن. تبدأ عند الاستلام. لاصق مشوّه قُبل بدون عدّ حقيقي. صندوق تالف وُقِّع عليه كـ"نظيف". مورد تخطّى إشعار الشحن المسبق فأصبح فريقك يرتجل عند وصول الشاحنة. هذه هي اللحظات التي تُدمّر دقة المخزون بصمت.</cite>

<cite index="13-1">فكّر في عملية الاستلام كقمع تحويل: الشاحنة تصل → التحقق → الفحص → استلام النظام → التخزين → مخزون مخزَّن. إذا انكسر أي خطوة في هذا القمع، تعاني العمليات التالية.</cite>

بمعنى آخر: **خطأ يحدث عند الاستلام يُضاعَف عشرات المرات** عبر كل أمر سحب وكل فاتورة وكل إجراء مخزني لاحق. الدقة هنا ليست خياراً — هي أساس كل شيء.

## أولاً: الإشعار المسبق بالشحنة (Advanced Shipping Notice — ASN)

### ما هو الـ ASN؟
<cite index="12-1">بمجرد التحقق من الـ ASN، يُجهّز المستودع مناطق التخزين ويُخلي المساحات وينظّم مسارات التخزين لتفادي الازدحام أثناء الاستلام.</cite>

الـ ASN هو إشعار إلكتروني يُرسله المورد قبل وصول الشحنة — يُعلم المستودع بالضبط بما سيصل، متى، وبأي تفاصيل.

### محتوى الـ ASN الكامل
```
بيانات الشحنة:
  □ رقم PO المرتبط
  □ تاريخ ووقت الشحن المتوقع
  □ رقم الشاحنة / شركة الشحن / رقم بوليصة الشحن (BOL)
  □ عدد الطرود الإجمالي (عدد البليتات / الكراتين)
  □ الوزن الإجمالي

بيانات البنود التفصيلية:
  □ رقم الصنف (SKU) ووصفه
  □ الكمية لكل بند
  □ أرقام الدفعات (Lot Numbers)
  □ تواريخ الانتهاء (للمواد ذات الصلاحية)
  □ الأرقام التسلسلية (للمعدات والأجهزة)
  □ وحدة القياس
```

### ما يفعله الـ ASN للمستودع قبل الوصول
```
الـ ASN يصل الساعة 8 صباحاً لشحنة تصل الساعة 2 ظهراً:

النظام يقوم تلقائياً بـ:
  ✅ تحجيز رصيف استلام خالٍ (Dock Door Scheduling)
  ✅ حساب العمالة اللازمة للتفريغ
  ✅ تحديد مناطق التخزين المبدئية لكل صنف
  ✅ طباعة أوراق الاستلام بأرقام Lot مسبقاً
  ✅ إشعار قسم الجودة بأنواع المواد القادمة للفحص
  ✅ حجز مساحة كافية في منطقة الاستلام والتخزين

النتيجة:
  بدون ASN: الشاحنة تصل → الفوضى → ساعات ضائعة
  مع ASN: الشاحنة تصل → كل شيء جاهز → تفريغ فوري
```

## ثانياً: جدولة أرصفة الاستلام (Dock Scheduling)

### مشكلة الازدحام في الأرصفة
<cite index="19-1">معظم عمليات الاستلام الواردة تفاعلية. الشاحنات تصل، موظفو الاستلام يكتشفون ما بداخلها، العمالة تتسابق للتفريغ، وأبواب الرصيف تنسد لأن ثلاث شاحنات وصلت في نفس فترة 30 دقيقة. الموردون يلومون المستودع، المستودع يلوم الموردين، ولا شيء يتحسن.</cite>

### نظام جدولة الأرصفة
```
بوابة المستودع تُظهر للمورد مواعيد متاحة:
  رصيف 1 — الاثنين 8-10 ص: محجوز (مورد الفولاذ)
  رصيف 1 — الاثنين 10-12: متاح ← المورد يحجز هنا
  رصيف 2 — الاثنين 8-10 ص: متاح
  رصيف 2 — الاثنين 10-12: محجوز (مورد الكيماويات)

عند الحجز:
  → المورد يدخل: عدد الطرود، نوع الشحنة، متطلبات خاصة
  → النظام يتحقق من توفر المعدات (رافعة؟ رصيف مرتفع؟)
  → تأكيد تلقائي + إرسال تعليمات الوصول للسائق
```

### مؤشر الوقت من الرصيف للمخزون (Dock-to-Stock Time)
<cite index="17-1">تقرير WERC DC Measures لعام 2025 يضع أفضل أداء لـ Dock-to-Stock تحت 3.5 ساعات. معدلات الشركات المتوسطة 12-24 ساعة.</cite>

```
الهدف لـ Kyvzon:
  مواد عادية: أقل من 4 ساعات
  مواد تحتاج تبريد / شروط خاصة: أقل من 2 ساعة
  مواد الفئة A (حرجة للإنتاج): أقل من 1 ساعة
```

## ثالثاً: خطوات الاستلام التفصيلية

### الخطوة 1: استقبال الشاحنة وفحص المستندات
```
عند وصول الشاحنة:
  □ التحقق من هوية السائق والشركة
  □ فحص ختم الشاحنة (Seal Number) قبل فتح الباب
  □ التحقق من بوليصة الشحن (BOL) ومطابقتها مع PO وASN
  □ تصوير حالة الشاحنة الخارجية قبل الفتح (توثيق قانوني)
  □ إذا الختم مكسور أو غير مطابق: إجراء خاص + إشعار فوري
```

### الخطوة 2: التفريغ والفحص الخارجي
```
□ التفريغ في منطقة الاستلام (Staging Area) — لا مباشرة للأرفف
□ فحص بصري لكل بليت/كرتون:
    - تشوهات؟ بلل؟ كسر؟ أثر حريق؟
    - إذا وُجد ضرر: تصوير فوري + تمييز بعلامة حمراء
    - التوقيع على BOL مع تحفظ "تحت الفحص"
□ عدّ الطرود الإجمالي مقابل BOL
    - مطابق → الانتقال للخطوة التالية
    - فرق → توثيق + إشعار قسم المشتريات فوراً
```

### الخطوة 3: العدّ والمسح التفصيلي (Detailed Count & Scanning)
```
موظف الاستلام يمسح كل وحدة بالماسح الضوئي:

للمادة الأولى — صفيحة فولاذ:
  مسح رمز Barcode/QR → يظهر على الشاشة:
  الصنف: RM-001-STEEL-2MM ✅ مطابق للـ PO
  الوزن القائم: 598.3 KG
  رقم الدفعة من المورد: BATCH-KH-2026-441
  تاريخ الانتهاء: لا ينطبق (فولاذ)

  النظام يقارن بالـ PO تلقائياً:
  المطلوب: 600 KG
  الوارد: 598.3 KG
  الفرق: -1.7 KG (-0.28%) ← ضمن حد التسامح 0.5%
  القرار: ✅ مقبول
```

### الخطوة 4: إدخال الاستلام في النظام (System GR Posting)

<cite index="16-1">عند إتمام التحقق، يجب تسجيل البضاعة في نظام إدارة المستودع. هذا يحوّل "بضاعة على الرصيف" إلى "مخزون حي". أخيراً، تُنقل البضائع إلى مواقع تخزينها المحددة (التخزين).</cite>

```
بعد إتمام العدّ:
  موظف يضغط "تأكيد الاستلام" في النظام

يحدث تلقائياً:
  ✅ المخزون يُحدَّث: +598.3 KG صفيحة فولاذ
  ✅ PO يُحدَّث: 598.3 من أصل 600 مستلَم (Open Balance: 1.7 KG)
  ✅ طلب فحص جودة IQC يُنشأ تلقائياً
  ✅ إشعار لقسم الجودة: "شحنة جاهزة للفحص"
  ✅ مهمة تخزين (Putaway Task) تُرسل لموظف المستودع
  ✅ إشعار لمخطط الإنتاج: "مادة X وصلت — متوفرة قريباً"
```

### الخطوة 5: الحجر الصحي انتظار الجودة (Quality Hold)
```
حالة المخزون بعد الاستلام وقبل الجودة:
  "مستلَم — في انتظار فحص الجودة"
  الموقع: منطقة الحجر الصحي QH-A3 (مميزة بعلامة صفراء)
  لا يمكن لأي أمر إنتاج استخدام هذه المادة

بعد موافقة الجودة:
  الحالة تتحول: "مُتاح للاستخدام"
  تُرسل مهمة التخزين النهائية لموظف المستودع
```

## رابعاً: معالجة انحرافات الاستلام (OS&D — Overages, Shortages, Damages)

### الزائد (Overage)
```
السيناريو: وصل 620 KG بدلاً من 600 KG

الخيارات:
  (أ) قبول الكمية الزائدة مع تعديل PO
      → PO يُعدَّل + إشعار للمشتريات لتعديل الفاتورة
  (ب) رفض الزائد وإعادته للمورد
      → يُحجز في منطقة الإعادة + وثيقة RTV

القرار يعتمد على: هل نحتاجها؟ هل سعرها مناسب؟
```

### الناقص (Shortage)
```
السيناريو: وصل 560 KG بدلاً من 600 KG

الإجراء التلقائي:
  → الـ 40 KG الناقصة تبقى "Open Balance" في PO
  → إشعار فوري للمشتريات
  → المشتريات تتواصل مع المورد: "متى الشحنة التكميلية؟"
  → إذا الفارق يؤثر على الإنتاج: تنبيه لمخطط الإنتاج
```

### التالف (Damage)
```
أنواع الأضرار:
  ضرر خارجي واضح عند الاستلام → رفض الشحنة كاملاً
  ضرر اكتُشف عند الفتح → توثيق + حجر + فتح NCR مع المورد
  تلف خفي اكتُشفه الجودة → معالجة عبر وحدة الجودة

الوثائق الإلزامية عند أي ضرر:
  □ صور موثّقة بالتاريخ والوقت
  □ وصف دقيق للضرر
  □ توقيع السائق إقراراً بالضرر
  □ إشعار شركة التأمين إذا الضرر جسيم
```

## خامساً: Cross-Docking — الشحن المباشر بدون تخزين

### ما هو Cross-Docking؟
مواد تصل للمستودع ولا تُخزَّن — تُنقل مباشرة من رصيف الاستلام لرصيف الشحن الصادر.

```
متى يُستخدم Cross-Docking؟
  □ مواد مطلوبة لأمر إنتاج عاجل الآن
  □ بضائع بضاعة جاهزة مؤكدة الشحن لعميل
  □ مواد تحتاج تحكماً بيئياً خاصاً (لا تتحمل التخزين المطوّل)
  □ توزيع ضخم لعدة وجهات يأتي موحداً ويُوزَّع

الميزة: يُلغي تكلفة التخزين + يُسرّع الوصول للإنتاج أو الشحن
```

## سادساً: إدارة تسميات الوحدات (Labeling / LPN)

### License Plate Number (LPN)
<cite index="13-1">كل بليت/كرتون/وحدة يُمسَح للتحقق من SKU، الكمية، رقم الدفعة، تاريخ الانتهاء، والأرقام التسلسلية. البليتات المختلطة تُفكَّك إذا لزم.</cite>

```
عند الاستلام، كل وحدة أو بليت يحصل على:
  LPN (رقم لوحة ترخيص داخلي):
    LPN-2026-0847-001 (البليت الأول من الشحنة)
    LPN-2026-0847-002 (البليت الثاني)

محتويات ملصق الـ LPN:
  □ رقم LPN (باركود + نص)
  □ رقم الصنف الداخلي
  □ الكمية
  □ رقم دفعة المورد
  □ رقم PO
  □ تاريخ الاستلام
  □ الموقع المستهدف (إذا عُرف)

فائدة LPN:
  كل حركة للبليت لاحقاً تُتتبَّع بمسح هذا الـ LPN
  من الرصيف → الحجر الصحي → رف B-12 → خط الإنتاج
  تاريخ كامل لكل بليت في أي لحظة
```

## ثامناً: ما يجب أن تتضمنه هذه الوحدة في Kyvzon

- **إدارة الـ ASN:** استلام وتحقق ومعالجة إشعارات الشحن المسبق
- **جدولة الأرصفة:** تقويم حجز يمنع الازدحام مع بوابة للموردين
- **واجهة الاستلام المحمولة:** تطبيق لموظف الاستلام بمسح الباركود
- **تلقائي GR Posting:** تحديث المخزون والـ PO والإشعارات فوراً
- **إدارة OS&D:** تدفق واضح لكل نوع انحراف مع توثيق
- **Quarantine Zone:** حالة خاصة للمخزون انتظار قرار الجودة
- **LPN / Labeling:** توليد وطباعة ملصقات داخلية عند الاستلام
- **Cross-Docking:** دعم الشحن المباشر بدون تخزين
- **لوحة الاستلام:** جدول الشحنات القادمة وحالة كل رصيف
- **تقارير Receiving:** Dock-to-Stock، OS&D، وإنتاجية الموظفين
