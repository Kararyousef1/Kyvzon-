---

## 1) ما هو Kyvzon؟

منصة ERP عربية (RTL) متعددة المستأجرين (multi-tenant SaaS) مبنية على:

| الطبقة | التقنية |
|---|---|
| الواجهة | React + TypeScript + Vite + TailwindCSS |
| قاعدة البيانات | Supabase (PostgreSQL 17) + RLS |
| الخلفية | Supabase Edge Functions (Deno) |
| الاختبارات | Vitest |
| التوجيه | React Router v6 |

**اللغة:** كل الواجهات والتوثيق والرسائل بالعربية، `dir="rtl"`.

## 2) قواعد التعامل مع المستخدم — إلزامية

المستخدم مهندس يتوقع مستوى «بروفيسور». نصّاً من كلامه:
> «نحتاج أن نبني هذه البوابة بدقة عالية جداً جداً … لن نخرج من وحدة أو من خطوة أثناء العمل حتى ننهيها بشكل كامل، كل التفاصيل يجب أن تكون موجودة.»

| القاعدة | التفصيل |
|---|---|
| **العربية دائماً** | إلا إن طلب غير ذلك صراحةً |
| **لا ملخصات سطحية** | يكره العموميات. كن محدداً: ما الملف، ما السطر، ما الخطأ |
| **الصدق قبل الاتساق** | إن كان تقرير سابق خاطئاً، صحّحه علناً ووثّق التصحيح |
| **لا Git push ولا `supabase db push`** | إلا بطلب صريح منه |
| **ميّز مستويات التحقق** | فحص ثابت ≠ Postgres محلي ≠ Supabase حقيقي ≠ متصفح حقيقي |
| **«هل جاهز؟»** | الجواب الصادق: مكتمل محلياً ≠ جاهز للإنتاج |

### القاعدة الذهبية
> **لا تُوثّق بأي SQL لم يُنفَّذ فعلياً.**
>
> هذه القاعدة وُلدت من ألم حقيقي: أخطاء كثيرة تُنشئ الدالة بنجاح ثم
> تفشل عند أول استدعاء. راجع `04-VERIFICATION-PLAYBOOK.md`.

## 5) أول أمر تشغّله في أي جلسة جديدة

```bash
cd /path/to/Kyvzon
npm ci          # node_modules لا يُحفظ بين الجلسات (~12 ثانية)
git remote -v   # إن كان فارغاً: git remote add origin <URL>
```

> ⚠️ `node_modules` و`.git/config` و`.pgtest` **لا تُحفظ** في لقطات
> مساحة العمل. توقّع غيابها وأعد بناءها.
