## الخلاصة في 10 نقاط

1. **العربية دائماً.** المستخدم مهندس ويكره الملخصات السطحية.
2. **لا `git push` ولا `supabase db push`** إلا بطلب صريح.
3. **لا تُوثّق بأي SQL لم يُنفَّذ فعلياً** — القاعدة الذهبية.
4. **ابنِ مختبر Postgres محلياً** قبل أي عمل على SQL (ملف 04).
5. **الـ shim يجب أن يحوي `ALTER DEFAULT PRIVILEGES`** وإلا لن تكتشف
   أخطاء الصلاحيات (سبب فشل `0268` عند المستخدم).
6. **`REVOKE FROM PUBLIC` لا يكفي** — اسحب من `anon, authenticated` صراحةً.
7. **أي وحدة جديدة تُسجَّل في 4 مواضع** وإلا اختفت لبعض المستخدمين.
8. **ممنوع:** `confirm()` · `prompt()` · `as any` · الحذف النهائي.
9. **الصفحات لا تلمس Supabase** — كل شيء عبر طبقة SDK.
10. **دقّق أي «نقص» مسجَّل** قبل العمل عليه — ثلاثة ادعاءات سابقة
    كانت خاطئة (ملف 06 §10).
